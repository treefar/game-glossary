# 前言

遊戲產業歷經數十年的發展，累積了大量的專業術語與設計概念。這些名詞不僅是玩家之間的共通語言，更是遊戲開發者必須精通的專業知識。當你在企劃會議上說「我們要做一個類魂的箱庭遊戲，戰鬥要有硬直和彈反機制」時，團隊中的每個人都必須能精確理解這些詞彙背後的設計意涵。

本指南以二十年以上的遊戲經驗為基礎，系統性地整理現世代遊戲中最重要的專有名詞，涵蓋基礎詞彙、遊戲設計哲學、類型分類、戰鬥機制、系統設計、多人遊戲、技術術語、敘事設計、產業實務、手遊機制、電競術語、AI 與新興技術，以及玩家社群黑話等十三大領域。每個名詞都附有英文原文、實際作品範例以及對遊戲開發的設計提醒，讓讀者不僅「知道這個詞」，更能「理解背後的設計邏輯」。

第二版相較初版，新增了閱讀正文前的「基礎速查」章節，讓完全新手也能順利進入後續的進階內容；補足了 MOBA、FPS、RPG 等基礎類型的完整定義；大幅擴充戰鬥機制章節，加入冷卻時間、架勢條、暴擊等高頻詞彙；更新了技術章節以涵蓋 NVIDIA DLSS 5 與路徑追蹤等 2026 年的最新進展；並新增一整章「遊戲圈黑話與玩家社群術語」，讓讀者能看懂實況、聊天室與遊戲論壇的日常用語。

讀完本指南，「我們要做一個類魂的箱庭遊戲，戰鬥要有硬直和彈反機制」這樣的句子，對你來說會像母語一樣自然。

# 基礎速查

在進入正文章節前，這一章先把遊戲世界中最基礎、最常出現的縮寫與概念一次交代完。這些詞會在後面每一章反覆出現，先在腦中有個印象，讀起來會順很多。把這一章當成一本工具書的「圖例說明」——不是第一章內容，而是閱讀第一章以後所需的共同語言。

## 一、最常見的遊戲類型縮寫

以下是玩遊戲、讀遊戲新聞、逛 Steam 標籤時最常撞見的類型縮寫。本章只做最簡定義，詳細介紹請見第二章。

- **RPG** `Role-Playing Game` — 角色扮演遊戲。玩家扮演角色、透過戰鬥或選擇逐漸成長。主要細分為日式 RPG（JRPG，如《最終幻想》）與西式 RPG（WRPG，如《巫師》《柏德之門》）。

- **ARPG** `Action RPG` — 動作角色扮演。將 RPG 的成長系統結合即時動作戰鬥，代表如《暗黑破壞神》《艾爾登法環》。

- **FPS** `First-Person Shooter` — 第一人稱射擊遊戲。玩家以角色的視角看出去，畫面中通常只看到自己的武器。代表如《決勝時刻》《鬥陣特攻》。

- **TPS** `Third-Person Shooter` — 第三人稱射擊遊戲。鏡頭在角色身後，能看到自己角色的動作。代表如《戰爭機器》《絕地求生》。

- **MOBA** `Multiplayer Online Battle Arena` — 多人線上戰鬥競技場。兩隊各 5 人、每人控制一名英雄、目標是摧毀對方基地。每局從零開始，強調團隊協作與即時戰術。代表如《英雄聯盟》《Dota 2》《傳說對決》。

- **RTS** `Real-Time Strategy` — 即時戰略遊戲。玩家同時指揮大量單位進行建造、採集、戰鬥，代表如《星海爭霸》《魔獸爭霸》《世紀帝國》。

- **MMO / MMORPG** `Massively Multiplayer Online (Role-Playing Game)` — 大型多人線上（角色扮演）遊戲。數百至數千名玩家共存於同一個持續性世界中。代表如《魔獸世界》《Final Fantasy XIV》。

- **ACT** `Action Game` — 動作遊戲的統稱。強調即時操作與戰鬥技巧，代表如《惡魔獵人》《魔兵驚天錄》。

- **AVG / ADV** `Adventure Game` — 冒險遊戲。重視劇情、解謎、探索而非戰鬥，代表如《逆轉裁判》《極樂迪斯可》。

- **SLG** `Simulation Game` — 模擬或策略遊戲（這個縮寫在中文圈較常指策略類）。包含模擬經營、戰棋、大戰略等子類。

- **SPG / RAC** `Sports Game / Racing Game` — 運動遊戲／競速遊戲。代表如《FIFA》《極限競速》。

## 二、最基礎的遊戲數值

這套數值體系源自早期的桌上角色扮演遊戲，是現代 RPG、動作遊戲、手遊幾乎所有系統的底層。

- **HP** `Hit Points / Health Points` — 生命值。歸零角色就會死亡或倒下。俗稱「血量」「血條」。

- **MP** `Magic Points / Mana Points` — 魔力值。施放技能或魔法所需的資源，俗稱「魔量」「藍量」（因介面常用藍色條呈現）。部分遊戲改稱「法力」「能量」「怒氣」等，本質相同。

- **EXP / XP** `Experience Points` — 經驗值。擊敗敵人或完成任務獲得，累積到閾值後升級。

- **LV / Lvl** `Level` — 等級。角色能力的總體指標，升級後屬性提升、解鎖新技能。

- **ATK / DEF** `Attack / Defense` — 攻擊力／防禦力。決定造成與承受的傷害多寡。

- **CRIT** `Critical Hit` — 暴擊（爆擊）。有機率觸發的高額傷害一擊，常見數值為「暴擊率」與「暴擊傷害」兩項。

- **DMG** `Damage` — 傷害值。造成或承受的傷害數字，常顯示為跳字。

## 三、最基礎的介面元素

- **HUD** `Head-Up Display` — 抬頭顯示。指畫面上疊加於遊戲世界之上的所有資訊元素，包括血條、彈藥數、小地圖、任務提示等。名稱源自軍機駕駛艙的抬頭顯示器。

- **UI** `User Interface` — 使用者介面。廣義泛指玩家能看到與操作的所有視覺元素，包括選單、按鈕、圖示等；狹義上與 HUD 略有區別。

- **UX** `User Experience` — 使用者體驗。指玩家操作遊戲的整體感受，是比 UI 更上位的設計概念。

- **小地圖** `Minimap` — 畫面邊角的縮小版地圖，顯示玩家位置、目標方向與周遭環境。

- **血條 / 能量條** `Health Bar / Resource Bar` — 以可視化長條呈現的數值，讓玩家一眼掌握狀態。設計重點是「變化時要明顯」——受傷時短暫閃紅、瀕死時震動等。

- **Tooltip** `Tooltip / Hover Text` — 滑鼠停留或選取物件時顯示的說明小框，用於解釋技能、裝備、狀態等。

## 四、頻率極高的英文縮寫

下列縮寫在 MOBA、MMO、FPS 的隊友聊天室中每場都會出現，也大量滲透到其他遊戲類型。詳細意義請對照後續章節，這裡先看個面熟。

- **CD** `Cooldown` — 冷卻時間。技能使用後必須等待才能再次施放。

- **CC** `Crowd Control` — 群體控制。使敵人無法行動的各種效果（暈眩、冰凍、定身等）。

- **AOE** `Area of Effect` — 範圍效果。一次影響多個目標的攻擊或技能。

- **DPS** `Damage Per Second` — 每秒傷害。也用來稱呼「負責輸出傷害」的角色定位。

- **Tank / 坦克** `Tank` — 承受傷害、保護隊友的角色定位，俗稱「肉盾」「神坦」。

- **Healer / 奶媽** `Healer` — 負責回復隊友血量的角色，俗稱「補師」「奶媽」。

- **Support / 輔助** `Support` — 不主攻輸出，而是透過增益、治療、控場協助隊友的角色。

- **Buff / Debuff** `Buff / Debuff` — 增益效果／減益效果。暫時提升或降低屬性的狀態。

- **Nerf / Buff** `Nerf / Buff (verb)` — 在版本更新語境下，Nerf 指削弱某角色或裝備，Buff 指增強。注意 Buff 在此是動詞用法，與上一條的名詞「增益效果」是同字雙義。

- **GG** `Good Game` — 好一場比賽。原為比賽結束的禮貌用語（由輸家先說），現已泛指「完蛋了」「結束了」的口語。

- **AFK** `Away From Keyboard` — 暫時離開鍵盤。泛指玩家人不在電腦前、角色原地不動的狀態。

- **NPC** `Non-Player Character` — 非玩家角色。由電腦控制的遊戲角色，包括任務發布者、商人、敵人等。

- **Boss** `Boss` — 頭目。關卡或區域中最強的敵人，通常有獨特機制與豐厚獎勵。

# 第一章：遊戲設計哲學與世界構建

遊戲的世界構建方式決定了玩家探索的自由度與遊戲的整體節奏。這是遊戲企劃最初也最關鍵的決策之一。在設計世界結構前，更根本的概念是「關卡設計」與「空間敘事」——它們是所有世界構建形式的底層工具。

### 關卡設計  `Level Design`

設計遊戲中單一空間（關卡、區域、場景）的學科。關卡設計師的工作是把遊戲的核心機制（跳躍、射擊、潛行等）佈置成具體的空間挑戰——決定敵人出現位置、地形起伏、掩體分布、光線引導、節奏變化等。好的關卡設計應該「教玩家使用機制」而不依賴文字教學——把玩家放進一個環境，他會自然學會要怎麼玩。

關卡設計與遊戲機制設計是兩個不同但緊密相關的職位：機制設計師決定「這個遊戲要有跳躍」，關卡設計師決定「玩家在這個關卡會在什麼時機、什麼地點、為什麼需要跳躍」。

> **▶ 代表作品**：*所有單人遊戲——特別是《超級瑪利歐》系列、《薩爾達傳說》系列、《最後生還者》系列、《半衰期》系列堪稱教科書*

> **★ 設計要點**：關卡設計的第一原則：玩家永遠知道自己要去哪裡（指引），永遠知道自己為什麼要去那裡（動機），永遠有多種方式到達那裡（選擇）。這三者缺一，體驗就會變差。

### 空間敘事  `Spatial Narrative`

透過空間本身來講述故事的設計手法，是關卡設計與敘事設計的交會點。空間敘事不依賴文字或對話，而是讓玩家在走過一個房間、打開一扇門、看見一扇窗景的瞬間，自然理解「這裡發生過什麼」。例如一間辦公室裡，桌上攤開的履歷與牆上的裁員通知，就說明了前任主人的處境。空間敘事的關鍵是「讓玩家自己拼湊真相」——這種主動解讀比被動觀看更有情感衝擊力。

> **▶ 代表作品**：*生化奇兵(BioShock)系列、半衰期 2(Half-Life 2)、最後生還者(The Last of Us)、回家(Gone Home)*

> **★ 設計要點**：空間敘事是獨立開發者最該掌握的敘事技術——因為它不需要昂貴的過場動畫或配音，只需要用心擺放場景物件。一個翻倒的椅子、一灘未乾的血跡、一張半寫的遺書，就能承載整段故事。

### 箱庭遊戲  `Hakoniwa`

箱庭（はこにわ）源自日文，原意為「微縮庭園」。在遊戲設計中，指的是在精心設計的封閉空間內，提供極高密度的互動與探索樂趣。與開放世界不同，箱庭遊戲追求的是「小而精」而非「大而廣」。每個關卡都像一座經過反覆打磨的縮小世界，玩家可以在其中自由探索並發現多種解決問題的方式。任天堂的宮本茂是這種設計哲學的代表人物，從《超級瑪利歐 64》開始便確立了這種設計典範。所謂「密度優先」的設計思維，意味著開發者將有限的資源全數投注在單一空間中，確保每一個可互動的物件、每一條隱藏通道、每一個視覺線索都經過精心安排，讓玩家無論往哪個方向探索都能獲得回報。

> **▶ 代表作品**：*超級瑪利歐 奧德賽(Super Mario Odyssey)、薩爾達傳說 王國之淚(Tears of the Kingdom)、超級瑪利歐 3D 世界、太空機器人(Astro Bot)*

> **★ 設計要點**：箱庭設計的核心在於「密度」而非「總量」。開發資源集中在有限空間內，讓每個角落都有探索價值。對獨立開發者來說，這是比開放世界更可行的選擇——不需要一百平方公里的地圖，只需要一平方公里的極致體驗。

### 開放世界  `Open World`

提供廣大的可自由探索地圖，玩家可以不受線性流程約束，自行決定探索的方向與順序。現代開放世界遊戲強調「看得到的地方都能去」的自由度，並以大量的支線任務、隨機事件、收集要素填充世界。但開放世界也面臨「公式化」的挑戰——當遊戲地圖足夠大卻內容密度不足時，玩家會感到「空洞」。所謂「興趣點」（Points of Interest, POI），是指地圖上吸引玩家前往探索的特殊地標或事件，例如敵人據點、寶箱位置、NPC 任務、特殊地形等。POI 的分佈密度與品質直接決定了開放世界是否令人流連忘返。近年來《薩爾達傳說 曠野之息》透過化學引擎（指遊戲中火、風、水、電等元素會依真實物理規則相互影響的系統）與自由攻略的設計，重新定義了開放世界的可能性。

> **▶ 代表作品**：*薩爾達傳說 曠野之息、巫師 3：狂獵、上古卷軸 5：無界天際、俠盜獵車手 5、艾爾登法環(Elden Ring)*

> **★ 設計要點**：開放世界的開發成本極高，需要大量的關卡設計師、美術資產與 QA 測試。設計時要特別注意 POI 的分佈密度——業界經驗法則是「玩家在任何位置環顧四周，至少要能看到一個值得前往的目標」。

### 半開放世界  `Semi-Open World / Hub-based World`

介於線性與完全開放之間的設計。遊戲由多個可探索的區域（稱為「Hub」，音譯「哈伯」，即中樞區域）組成，各區域內部有一定自由度，但區域之間的開放有先後順序或條件限制。這種設計既能提供探索感，又能控制敘事節奏與開發成本。Hub-based 的結構讓開發團隊可以分區域逐步製作，同時確保每個區域的品質。

> **▶ 代表作品**：*戰神(God of War, 2018)、星際大戰 絕地：組織殞落、戰神：諸神黃昏、最終幻想 VII 重生、死亡擱淺(Death Stranding)*

> **★ 設計要點**：適合中型開發團隊，可以在可控範圍內提供探索樂趣，同時確保敘事體驗的完整性。每個 Hub 區域建議有獨特的視覺主題與遊戲機制，讓玩家對每個新區域都保持期待。

### 沙盒遊戲  `Sandbox`

強調玩家創造與自由互動的遊戲類型。與開放世界不同，沙盒遊戲的核心不在於探索預設內容，而在於玩家自行定義目標並創造內容。遊戲提供工具與規則，玩家則提供想像力。好的沙盒遊戲就像一盒樂高——零件本身很簡單，但組合的可能性幾乎無限。

> **▶ 代表作品**：*當個創世神(Minecraft)、泰拉瑞亞(Terraria)、蓋瑞模組(Garry's Mod)、機器磚塊(Roblox)、模擬城市系列*

> **★ 設計要點**：沙盒遊戲的留存率極高，但新手引導是最大挑戰。設計時需要在「自由度」與「引導性」之間找到平衡——太多引導會破壞自由感，太少引導會讓新玩家不知所措。建議設計漸進式的教學系統，讓玩家在遊玩過程中自然學會進階機制。

### 線性遊戲  `Linear Game`

遊戲流程按照開發者預設的順序推進，玩家沿著固定路徑前進。這並非負面詞彙——線性設計能提供更精確的敘事節奏控制、更細緻的關卡設計、更強烈的電影化演出。在成本控制上也更可預測。線性遊戲的精髓在於「讓玩家感覺不到線性」，透過精心的空間設計（例如岔路的假象）、鏡頭語言引導、節奏變化來維持玩家的沉浸感。

> **▶ 代表作品**：*最後生還者(The Last of Us)系列、秘境探險(Uncharted)系列、惡靈古堡系列、惡魔獵人系列*

> **★ 設計要點**：線性設計的最高境界是「隱性引導」——玩家以為自己在自由探索，實際上卻被巧妙地引向設計好的路徑。光線、色彩對比、聲音引導都是常見的手法。

### 程序化生成  `Procedural Generation`

透過演算法自動生成遊戲內容（地圖、關卡、物品、敘事等）的技術。可以極大地擴展遊戲內容量，提供每次遊玩都不同的體驗。但純程序化生成可能導致內容同質化，因此現代遊戲常採用「程序化生成＋手工調整」的混合方式。所謂「種子」（Seed）系統，是指用一個特定的數字或字串作為演算法的初始參數，相同的種子永遠會生成完全相同的結果。這讓開發者可以復現特定的生成結果來除錯，也讓玩家可以分享有趣的種子給朋友體驗同樣的關卡。

> **▶ 代表作品**：*無人深空(No Man's Sky)、洞穴探險(Spelunky)、死亡細胞、黑帝斯(Hades)、暗黑破壞神系列*

> **★ 設計要點**：程序化生成需要大量的測試來確保生成結果的品質。建議設計種子系統以便於復現與除錯，同時設定「規則約束」確保生成的內容在可玩性與美觀性上都達標——例如確保地圖永遠有一條可通行的路徑。

### 湧現式遊玩  `Emergent Gameplay`

玩家透過遊戲系統之間的交互作用，創造出開發者未預設的遊玩體驗。所謂「系統性設計」（Systemic Design），是指遊戲中的各種機制（火焰、風力、水流、磁力等）不是各自獨立運作，而是能夠相互影響、產生連鎖反應。例如在《曠野之息》中，玩家可以先用火箭點燃草地產生上升氣流，再利用滑翔翼飛到高處，最後從空中射出炸彈箭解決敵人——這個解法完全是玩家自己「發明」的。

> **▶ 代表作品**：*薩爾達傳說 曠野之息、神諭：原罪 2、諾伊塔(Noita)、巴巴是你(Baba Is You)*

> **★ 設計要點**：設計系統時，讓不同機制能彼此交互是關鍵。比起預設答案，提供「工具箱」讓玩家自行組合更能產生驚喜。開發時建議建立一張「系統交互矩陣表」，列出所有系統之間的互動關係並逐一測試。

# 第二章：遊戲類型與分類

遊戲類型的分類正在變得越來越細緻。傳統的「RPG」「ACT」分類已不足以描述現代遊戲的特色，因此出現了大量以「類＋代表作」命名的新類型。理解這些類型對於遊戲企劃、行銷定位都至關重要——在 Steam 等平台上，精確的類型標籤直接影響遊戲能否被目標玩家找到。

本章分四節：先在「基礎類型速查」補完 RPG、FPS、MOBA 等所有現代子類型的父類定義；接著依序介紹以經典作品命名的類型、Roguelike 家族、以及現代新興的各種重要類型。

## 二之一：基礎類型速查

這節整理現代遊戲最根本的幾個類型框架。後面章節所說的「類魂」「Hero Shooter」「Soulslike-Metroidvania」都建立在這些基礎類型之上。

### 角色扮演遊戲  `RPG (Role-Playing Game)`

玩家扮演一個或多個角色，透過戰鬥、探索、對話累積經驗與裝備，逐步讓角色從弱小成長到強大。RPG 的核心是「成長感」——每一次升級、每一件新裝備、每一個新學會的技能都應該被玩家清楚感知。依文化風格大致分為日式 RPG（JRPG，著重劇情與角色、多採回合制戰鬥）、西式 RPG（WRPG，著重自由度與選擇、多採即時戰鬥）、動作 RPG（ARPG，戰鬥採即時動作）三大支系。

> **▶ 代表作品**：*最終幻想(Final Fantasy)系列、勇者鬥惡龍、柏德之門 3、巫師 3、暗黑破壞神系列、艾爾登法環*

> **★ 設計要點**：RPG 的黏著度來源是「下一級的誘惑」——讓玩家永遠覺得「再打一場就能升級」「再一個任務就能拿到新裝備」。這需要升級曲線與獎勵節奏的精密設計。

### 第一人稱射擊 / 第三人稱射擊  `FPS / TPS`

FPS（First-Person Shooter）以角色的第一人稱視角遊玩，畫面中通常只看到武器與雙手，強調沉浸感與瞄準精度；TPS（Third-Person Shooter）鏡頭在角色身後，能看到自己角色的全身動作，適合強調角色造型與走位的遊戲。兩者的核心機制相同（瞄準、射擊、換彈、掩體），差別在鏡頭與空間感。

> **▶ 代表作品**：*FPS：決勝時刻、戰慄時空、毀滅戰士；TPS：戰爭機器(Gears of War)、絕地求生、漫威蜘蛛人*

> **★ 設計要點**：第一人稱的代入感最強但容易暈 3D；第三人稱更適合角色扮演體驗。部分遊戲提供切換選項（如《電馭叛客 2077》座駕切換），但要注意兩種視角對關卡尺度、UI 位置、戰鬥節奏的要求不同。

### 多人線上戰鬥競技場  `MOBA (Multiplayer Online Battle Arena)`

兩隊各 5 人的團隊競技類型，每人控制一名英雄，目標是摧毀對方基地（通常稱為主堡 Nexus、基地 Ancient 等）。地圖通常為三條路（上路 Top、中路 Mid、下路 Bot）加野區（Jungle）的對稱結構。每局從零開始——無論你之前練了多久，進入比賽時大家都是一級——透過擊殺小兵（Farm）、英雄（KDA）、野怪（包括俗稱「肥龍」「小龍」「巴龍」的野區大型目標）來累積金錢與經驗，購買裝備、升級技能。

MOBA 的策略深度來自三個層次：英雄組合（陣容搭配與對線剋制）、對線操作（補兵、消耗、換血、Gank 反應）、團隊宏觀（資源分配、節奏掌控、團戰時機）。源自《魔獸爭霸 3》玩家自製地圖 DotA，獨立成類型後成為全球最大電競類別之一。

> **▶ 代表作品**：*英雄聯盟(League of Legends)、Dota 2、傳說對決(Arena of Valor)、王者榮耀*

> **★ 設計要點**：設計 MOBA 的最大挑戰是英雄平衡與學習曲線——要有 100+ 位英雄但又要每一位都有可玩性；要有足夠深度讓高手鑽研但又不能讓新手完全看不懂。《聯盟戰棋》式的簡化版本（自走棋）是 MOBA 太陡峭的學習曲線催生出的「輕量版」。

### 大型多人線上角色扮演  `MMORPG (Massively Multiplayer Online RPG)`

數百至數千名玩家共存於同一個「持續性世界」中的 RPG——你下線後這個世界不會停止運作，別的玩家仍在裡面活動。核心特色包括：角色長期養成（可能玩上千小時）、公會與社交系統、分工明確的團隊副本（坦克／輸出／治療的「聖三位一體」）、經濟系統（玩家間交易與拍賣場）、持續更新的新內容（稱為「資料片」或「版本」）。MMORPG 是網路遊戲的開山祖類型，雖然熱度不如 2000 年代高峰，但仍有穩定的長青作品。

> **▶ 代表作品**：*魔獸世界(World of Warcraft)、Final Fantasy XIV、劍靈、天堂、黑色沙漠、Lost Ark*

> **★ 設計要點**：MMO 的成敗不在於機制設計而在於「社群感」——玩家留下來不是因為遊戲好玩，而是因為公會朋友還在線上。設計時應優先考慮社交工具（公會系統、語音整合、組隊便利性）而非單純的戰鬥深度。

### 英雄射擊  `Hero Shooter`

FPS 的現代變體，每名玩家從一組預設「英雄」中選擇，每位英雄有獨特的武器、技能組、被動能力。這讓原本「人人拿槍一樣強」的 FPS 變成「五花八門的角色扮演式射擊」——有人丟盾牌、有人飛牆壁、有人放音波大招。英雄射擊強調角色扮演而非純粹槍法，更考驗團隊組合與技能配合。

> **▶ 代表作品**：*鬥陣特攻(Overwatch) 1/2、特戰英豪(Valorant)、Apex 英雄、漫威 Rivals*

> **★ 設計要點**：設計英雄射擊時要平衡「獨特性」與「公平性」——每個英雄要有一眼看出的識別度（不同槍感、不同技能）但整體強度要接近。最容易犯的錯誤是做出「無腦強」的英雄把戰術層次拉到一維（只有選對英雄才能贏）。

### 戰術射擊  `Tactical Shooter`

強調戰術紀律與資訊博弈的 FPS 子類。特徵包括：一命制（死了不能重生直到下一回合）、經濟系統（每回合賺錢買武器）、定點攻防（一隊進攻、一隊防守固定地圖）、高致命性（被打中一槍就可能死）。節奏比一般 FPS 慢、更重視靜聽腳步、牆角偷窺（Peek）、與隊友資訊共享。與 Boomer Shooter 的「快速移動、血量爆炸」幾乎是對立光譜。

> **▶ 代表作品**：*反恐菁英 2(Counter-Strike 2)、特戰英豪(Valorant)、虹彩六號：圍攻行動、SWAT 4*

> **★ 設計要點**：戰術射擊的核心樂趣是「資訊戰」——你不知道敵人在哪、聽到腳步、推斷位置、決定要偷推還是退守。地圖設計決定一切：要有複雜的角度但又不能太複雜、要有狙擊點但又不能讓狙擊手獨大。

### 節奏遊戲  `Rhythm Game`

玩家需要配合音樂節拍輸入指令的遊戲類型。判定通常分「Perfect / Great / Good / Miss」多個等級，追求「全 Perfect」（All Perfect）是高手的終極目標。近年 VR 節奏遊戲（Beat Saber）將這個類型推上新高峰。

> **▶ 代表作品**：*太鼓之達人、DJMAX 系列、Beat Saber、友情之類、幾何衝刺*

> **★ 設計要點**：節奏遊戲的輸入延遲容忍度極低——毫秒級的延遲就會破壞手感。提供「延遲校準」功能是這類遊戲的標配。

### 視覺小說  `Visual Novel (VN)`

以文字敘事為核心、搭配角色立繪與背景圖的遊戲類型。遊玩主要是「閱讀」——點擊繼續、偶爾在分歧點做選擇。視覺小說在日本是成熟市場，分為純敘事的 Kinetic Novel（沒有選擇）與分支豐富的 Branching VN。許多經典作品（如《428》《Steins;Gate》）都有極高的劇情深度。

> **▶ 代表作品**：*428：被封鎖的澀谷、Steins;Gate、逆轉裁判、AI：夢境檔案、電擊文庫 FIGHTING CLIMAX*

> **★ 設計要點**：視覺小說的技術門檻最低（有 Ren'Py 等免費引擎），是獨立創作者練習敘事設計的理想起點。但正因門檻低，市場競爭的不是技術而是「故事本身夠不夠好」。

### 恐怖遊戲  `Horror Game`

以製造恐懼、不安、緊張為核心體驗的遊戲類型。主要分兩大流派：生存恐怖（Survival Horror，強調資源匱乏、怪物凶猛，如早期《惡靈古堡》），以及心理恐怖（Psychological Horror，強調氛圍與未知感、直接的怪物反而較少，如《沉默之丘》《P.T.》）。Jump Scare（突發驚嚇）是短效工具，真正高級的恐怖依賴「預期感」——讓玩家知道「有東西要發生」但不知道是什麼、何時發生。

> **▶ 代表作品**：*惡靈古堡系列、沉默之丘、P.T.、Outlast 系列、Phasmophobia、心靈殺手 2*

> **★ 設計要點**：恐怖遊戲的節奏是關鍵——不能一路都嚇，要有「喘息段」讓玩家誤以為安全，再在鬆懈時出手。聲音設計比視覺更重要；畫面再嚇人也不如一個突如其來的腳步聲。

### 潛行遊戲  `Stealth Game`

玩家必須避免被敵人發現、透過暗殺或繞路達成目標的類型。核心機制包括：敵人視野錐（Sight Cone）、聲音半徑（Sound Radius）、警覺等級（Alert Level，通常分綠／黃／紅三段）、藏屍體（避免其他敵人發現）、偽裝系統等。與戰鬥為主的動作遊戲不同，潛行遊戲的失敗通常只是「被發現」而非「被殺」——好的潛行遊戲讓玩家寧願重讀存檔也不想正面戰鬥。

> **▶ 代表作品**：*潛龍諜影(Metal Gear Solid)系列、刺客任務(Hitman)系列、冤罪殺機(Dishonored)、薩爾達傳說 王國之淚的潛行段落*

> **★ 設計要點**：潛行遊戲的核心挑戰是「讓敵人顯得聰明但不過度」——太笨顯得遊戲沒挑戰，太聰明（例如永遠知道你在哪）會讓玩家挫折。關鍵在於「AI 的視覺與聽覺要遵循玩家能預測的規則」。

### 塔防  `Tower Defense (TD)`

玩家在預設路徑沿線建造防禦塔，阻止一波波敵人抵達終點的策略類型。每一波之間有準備時間讓玩家規劃新塔位、升級舊塔、調整策略。變體包括非路徑式塔防（敵人會自尋路徑）、結合 RPG 的塔防（塔可以練等）、結合 FPS 的塔防（玩家自己也是一座「塔」）等。

> **▶ 代表作品**：*王國保衛戰(Kingdom Rush)系列、植物大戰殭屍、明日方舟（以塔防為核心的手遊）、Sanctum、Orcs Must Die*

> **★ 設計要點**：塔防的核心數值是「單位時間輸出 vs 敵人血量增長」。平衡性設計要讓玩家「感覺差一點就輸」——太寬鬆沒緊張感，太嚴苛讓人挫折。波次節奏設計要有高低潮，不能每波都一樣壓力。

### 4X 與大戰略  `4X & Grand Strategy`

4X 指 eXplore（探索）、eXpand（擴張）、eXploit（開發）、eXterminate（殲滅）四個核心玩法的策略遊戲，代表是《文明》系列與《Stellaris》。大戰略（Grand Strategy）則是模擬整個國家／文明在數百年時間尺度上運作的策略遊戲，涵蓋外交、經濟、宗教、軍事、科技等全方位決策，以 Paradox Interactive（P 社）的系列作為代表。兩者都是「一局玩一整晚」的長時間遊戲類型，玩家黏著度極高。

> **▶ 代表作品**：*文明(Civilization)系列、Stellaris、十字軍之王 3(Crusader Kings III)、歐陸風雲 4、維多利亞 3*

> **★ 設計要點**：這類遊戲的學習曲線通常陡峭（UI 上幾十個按鈕、十幾個資源），但一旦上手就成癮。設計時的取捨是：要不要降低入門門檻？過度簡化會失去硬派玩家，過於複雜則失去新玩家。P 社的解法是推出許多 DLC 讓系統逐步疊加。

### 模擬經營  `Tycoon / Management Sim`

玩家扮演管理者，建造並經營某種事業（主題樂園、醫院、城市、動物園、餐廳等），處理財務、員工、顧客、設施等多層面的挑戰。核心樂趣是「把一個亂七八糟的系統整理到順暢運作」的成就感。與沙盒的差別在於：經營遊戲有明確的數值目標（利潤、滿意度等），沙盒則完全讓玩家自訂目標。

> **▶ 代表作品**：*過山車大亨系列、雙點醫院、模擬城市系列、美麗新都：斯凱萊、動物園之星、Project Hospital*

> **★ 設計要點**：經營遊戲的平衡在於「總是有新問題」——玩家剛解決財務困境，員工就開始抗議；調好員工，顧客又不滿意。這種持續的「打地鼠」感是讓玩家黏著的核心。

## 二之二：以經典作品命名的類型

### 類魂遊戲  `Soulslike`

以 FromSoftware 的《黑暗靈魂》系列為典範的遊戲類型。核心特徵包括：高難度但公平的戰鬥、死亡懲罰（喪失經驗值或貨幣，且只有一次機會回到死亡地點取回）、精心設計的關卡捷徑（透過打開門或啟動電梯將遠處的路徑連回安全點）、碎片化環境敘事（故事不靠過場動畫，而是藏在物品說明、NPC 對話與場景細節中）、耐力管理戰鬥（每次攻擊、翻滾、格擋都消耗耐力條，用光就無法行動）、所有敵人包括 Boss 都能透過學習攻略模式來擊敗。

> **▶ 代表作品**：*黑暗靈魂(Dark Souls)系列、血源詛咒、隻狼：暗影雙死、艾爾登法環、P 的謊言、仁王 2、黑神話：悟空*

> **★ 設計要點**：類魂遊戲的難度不是「難而已」，而是「嚴格但公平」。每次死亡都應讓玩家感到「是我的問題」而非「遊戲的問題」。敵人攻擊必須有清晰的預兆動作（前搖），讓玩家有反應的時間與學習的空間。

### 類銀河戰士惡魔城  `Metroidvania`

結合《銀河戰士》與《惡魔城》特色的 2D 動作探索遊戲。核心設計為：一張相互連通的大地圖、透過獲得新能力來解鎖新區域（稱為「能力門檻」Ability Gating，例如取得二段跳後才能到達高處平台）、回訪舊區域發現新秘密（Backtracking，利用新能力打開先前無法通過的通道）。這種「探索→獲得能力→解鎖新路→再探索」的循環提供了強烈的成就感。

> **▶ 代表作品**：*空洞騎士(Hollow Knight)、死亡細胞、聖靈之光系列、銀河戰士 生存恐懼、暗影火炬城*

> **★ 設計要點**：Metroidvania 的地圖設計是靈魂。建議先畫出完整的「能力獲得順序圖」與「區域解鎖流程圖」，確保探索路徑合理且有多條可選路線，避免玩家在大地圖中迷失方向——適時提供地圖系統或路標提示。

### 類吸血鬼倖存者  `Vampire Survivors-like / Bullet Heaven`

2022 年《吸血鬼倖存者》引爆的新興類型。玩家僅需控制移動方向，攻擊則自動執行。遊戲核心在於：每次升級時從隨機選項中選擇武器或能力來構築 Build（角色配置）、隨時間不斷增加的敵人數量與強度、「數字膨脹」帶來的渺小感轉變為無雙感——開局時被三隻敵人追著跑，後期一招清掉滿畫面的上千隻敵人。所謂「協同效果」（Synergy），是指兩個以上的武器或能力組合後產生遠超各自效果總和的強力效果。

> **▶ 代表作品**：*吸血鬼倖存者、布洛塔托(Brotato)、苦痛大廳、靈魂石倖存者、HoloCure*

> **★ 設計要點**：這類遊戲的開發門檻低但市場競爭激烈。差異化的關鍵在於 Build 組合的深度與 Synergy 設計——讓玩家發現「原來這兩個能力一起用會這麼強！」的驚喜時刻是留住玩家的核心體驗。

### 割草遊戲  `Musou / Warriors-style`

源自光榮《真．三國無雙》系列的遊戲類型。玩家操控強力角色，在戰場上一次擊敗數十乃至數百名敵人，強調的是「無雙」的爽快感。日文「無雙」（むそう）一詞本身就代表了這種「一騎當千」的遊戲體驗。中文遊戲圈則以「割草」形象地描述大批量殲滅敵人的快感——敵人就像草地上的雜草，被玩家一刀一片地收割。這類遊戲的核心體驗是「力量幻覺」（Power Fantasy，遊戲設計用語，指刻意讓玩家感受到遠超現實的強大感）。

> **▶ 代表作品**：*真．三國無雙系列、薩爾達無雙、海賊無雙、火焰之紋章無雙*

> **★ 設計要點**：設計時要讓玩家感受到自己的強大，但又不能完全沒有挑戰。適時加入精英敵人、Boss 戰或戰場局勢變化（例如友軍陷入危機）來打破單調的收割節奏，製造張力與緩急之分。

## 二之三：Roguelike 與其變體

### Roguelike  `Roguelike`

源自 1980 年的遊戲《洛格》，嚴格定義包括：永久死亡機制（Permadeath，角色死亡後失去所有進度，必須從頭開始）、程序化生成關卡（每次遊玩的地圖布局都不同）、回合制戰鬥、基於方格的移動。根據 2008 年「柏林詮釋」（Berlin Interpretation，一份由 Roguelike 開發者社群共同制定的定義文件，可視為 Roguelike 的「憲法」），這些是定義 Roguelike 的核心要素。符合全部條件的才是「正統」Roguelike，部分符合的則歸類為 Roguelite。

> **▶ 代表作品**：*NetHack、地城爬行石湯、庫德之洞、Cogmind*

> **★ 設計要點**：傳統 Roguelike 的受眾較窄，但其設計哲學影響深遠。永久死亡機制讓每一步決策都充滿重量感——因為你知道一個錯誤就可能葬送數小時的努力。

### Roguelite  `Roguelite`

保留 Roguelike 的部分特徵（程序化生成、每局重新開始），但加入了「永久進度」（Meta-progression）機制。所謂 Meta-progression，是指在「局外」（跨越單次遊玩的範圍）累積的永久成長，例如：每次死亡後可以用收集的貨幣解鎖新武器或永久提升基礎能力。這意味著即使這一局失敗了，你的努力也不會完全白費，下一局會因為解鎖了新選項而有不同的體驗。這大幅降低了永久死亡的挫折感，使這類遊戲更受大眾歡迎。

> **▶ 代表作品**：*黑帝斯(Hades)、死亡細胞、殺戮尖塔(Slay the Spire)、以撒的結合、挺進地牢、巴拉特羅(Balatro)*

> **★ 設計要點**：Roguelite 的設計關鍵在於「局內隨機」與「局外成長」的平衡。永久進度不能太強以致於讓遊戲變成「刷等級就能過關」，削弱每局的緊張感；也不能太弱讓玩家感覺死亡沒有收穫。理想狀態是每次死亡都讓玩家想說「再來一局」。

## 二之四：現代新興與重要類型

### 沉浸式模擬  `Immersive Sim`

強調玩家自由度與多元解決方案的遊戲類型。遊戲世界是一個遵循一致規則的「模擬」環境，玩家可以透過戰鬥、潛行、駭客、社交等多種方式解決問題。核心理念是「玩家的創意永遠被尊重」——如果玩家想用物理引擎把箱子疊起來翻過高牆而不是找鑰匙開門，遊戲就應該允許這麼做。這類遊戲的開發難度極高，因為每個關卡都必須支援多種接近方式，測試負擔極重。

> **▶ 代表作品**：*駭客任務(Deus Ex)系列、冤罪殺機(Dishonored)系列、獵魂(Prey, 2017)、System Shock*

> **★ 設計要點**：設計時最重要的原則是「系統一致性」——所有規則在所有場景都要成立。如果火焰可以點燃木箱，那所有木製物體都應該能被點燃。玩家一旦發現規則不一致，沉浸感就會立刻瓦解。

### 抽取式射擊  `Extraction Shooter`

玩家帶著自己的裝備進入地圖、在地圖中搜刮戰利品與物資、然後必須在時限內到達撤離點安全撤離才能保留所有成果。如果在撤離前死亡，不僅失去搜刮的戰利品，連自己帶進去的裝備也會全部喪失。這種「高風險高報酬」的設計創造了極度緊張的遊戲體驗——每一個腳步聲、每一扇門後面都可能是敵人。

> **▶ 代表作品**：*逃離塔科夫(Escape from Tarkov)、暗與暗、三角洲行動、決勝時刻：戰區*

> **★ 設計要點**：經濟系統是抽取式射擊的命脈。裝備的價值感、戰利品的稀有度、失去裝備的痛苦感三者必須精心平衡。如果頂級裝備太容易獲得，失去它就不心疼；如果太難獲得，玩家會不敢帶出去用。

### 大逃殺  `Battle Royale`

大量玩家（通常 60 至 100 人）投入同一張不斷縮小的地圖，最後存活的玩家或隊伍獲勝。核心機制包括：著陸點選擇（跳傘決定起始位置）、地圖拾取裝備（開局時身無寸鐵，需要在地圖中搜刮武器與護甲）、安全區域縮減（通稱「毒圈」或「縮圈」，區域外的玩家會持續受到傷害，迫使所有人向中心移動）。自 2017 年起爆發式成長，持續至今仍是主流類型。

> **▶ 代表作品**：*絕地求生(PUBG)、要塞英雄(Fortnite)、Apex 英雄、決勝時刻：戰區*

> **★ 設計要點**：大逃殺的核心張力來自「縮圈」機制強迫玩家交戰，以及「一局定輸贏」的緊迫感。設計時要注意前期搜裝與後期激戰的節奏比例，避免前期過於無聊或後期過於混亂。

### Boomer Shooter  `Boomer Shooter / Retro FPS`

致敬 1990 年代經典第一人稱射擊遊戲的現代作品，特色包括極快的移動速度、大量敵人、多樣化武器庫、迷宮式關卡設計、地板拾取武器與血包（而非自動回血）。名稱中的「Boomer」指的是對舊時代的懷念（並非字面上的「嬰兒潮世代」）。近年來這個類型經歷了強勁的復興，證明了快節奏、重手感的 FPS 依然有廣大市場。與 Tactical Shooter 幾乎是光譜的對立兩端。

> **▶ 代表作品**：*DUSK、究極殺陣(Ultrakill)、Prodeus、Ion Fury、Warhammer 40K: Boltgun*

> **★ 設計要點**：這類遊戲證明了「手感」（Game Feel）的極端重要性。玩家移動時的慣性與加速感、武器切換的流暢度、擊中敵人時的視覺與聽覺反饋都是決定遊戲品質的核心要素。

### 牌組構築  `Deckbuilder / Deckbuilding`

遊戲過程中逐步構築自己的牌組，每張牌代表一個動作或效果。與傳統集換式卡牌遊戲（TCG, Trading Card Game）的最大差異在於：TCG 是在遊戲開始前就組好牌組，而 Deckbuilder 的牌組是在遊戲過程中一張一張地即時組裝的。每次戰鬥或事件後都能獲得新卡牌，同時也可以移除不需要的牌來精簡牌組。結合 Roguelite 機制後成為近年最成功的獨立遊戲類型之一。

> **▶ 代表作品**：*殺戮尖塔(Slay the Spire)、巴拉特羅、怪物火車、邪惡冥刻、Griftlands*

> **★ 設計要點**：牌組構築的樂趣在於「組合發現」。設計時要確保卡牌之間有足夠的協同效應（Synergy），讓玩家能發現強力的 Combo——例如一張牌讓所有攻擊附帶中毒，另一張牌對中毒敵人造成雙倍傷害，兩者結合就是爆炸性的組合。

### 自走棋  `Auto Battler / Auto Chess`

玩家購買並佈置棋子（角色），戰鬥則完全自動進行，玩家無法操控。策略核心在於：陣容組合（哪些角色搭配在一起能觸發羈絆加成）、經濟管理（何時存錢賺利息、何時花錢升級或刷新商店）、站位佈局（前排後排的位置影響角色的生存與輸出）。源自《Dota 自走棋》模組，後來獨立為一個完整類型。

> **▶ 代表作品**：*聯盟戰棋(Teamfight Tactics)、Dota Underlords、Auto Chess*

> **★ 設計要點**：自走棋的核心樂趣是「經濟決策」。所謂「連勝／連敗策略」是關鍵設計：連勝給額外獎勵金讓強者更強，連敗則讓弱者優先選秀追趕，形成動態平衡。

### 工廠建造  `Factory Builder / Automation Game`

玩家設計並建造自動化生產線，將原料透過一連串的加工步驟（採礦→冶煉→組裝→包裝等）製成成品。遊戲的樂趣在於優化產線效率（消除瓶頸）、解決物流問題（輸送帶怎麼配置才不會塞車）、不斷擴展規模。被稱為「工程師的遊戲」，因為核心遊玩非常近似實際的系統設計與最佳化思維。

> **▶ 代表作品**：*異星工廠(Factorio)、幸福工廠(Satisfactory)、戴森球計畫、Shapez*

> **★ 設計要點**：工廠建造的玩家黏著度極高（Factorio 在 Steam 上的平均遊戲時間超過百小時）。設計時要確保「複雜度曲線」平滑，每次引入新機制都搭配足夠的過渡期，讓玩家慢慢學習而不是一次被淹沒。

### 生存工藝  `Survival Craft`

玩家在危險環境中採集資源、製作工具與武器、建造庇護所、管理生存數值。所謂「生存數值」通常包括飢餓值（需要吃東西）、口渴值（需要喝水）、體溫值（需要保暖或降溫）、生命值（受傷需要治療）等。玩家必須在探索、戰鬥與維持生存之間取得平衡。這是過去十年來最穩定的熱門類型之一。

> **▶ 代表作品**：*英靈神殿(Valheim)、深海迷航、幻獸帕魯、Rust、森林、Enshrouded*

> **★ 設計要點**：生存數值的消耗速度是體驗設計的關鍵——太快會讓玩家疲於奔命只忙著找食物，太慢則失去生存的緊迫感。建議讓玩家在中期就能建立穩定的食物來源，將注意力轉移到探索與戰鬥上。

### 步行模擬器  `Walking Simulator`

以探索與敘事為主的遊戲，幾乎沒有傳統遊戲機制（戰鬥、解謎等）。玩家主要透過行走、觀察環境、閱讀文件、與物件互動來體驗敘事。雖然「步行模擬器」最初是玩家社群中帶有貶義的標籤（暗示遊戲「只能走路」），但現在已被廣泛接受為正式的類型名稱。這類遊戲證明了遊戲可以是強大的敘事媒介。

> **▶ 代表作品**：*艾迪芬奇的回憶、看火人(Firewatch)、回家(Gone Home)、Dear Esther*

> **★ 設計要點**：環境設計、音效設計、空間敘事是成功的關鍵。每個房間、每個物件都應該在講述故事的一部分。節奏控制也很重要——適時加入互動性較高的段落來避免玩家失去興趣。

### 農場／生活模擬  `Farm Sim / Life Sim / Cozy Game`

強調放鬆、經營、社交的遊戲類型。玩家經營農場、與 NPC 建立關係、依季節變化計劃活動。近年「Cozy Game」（舒適遊戲）一詞越來越常用，涵蓋所有低壓力、輕鬆愉快的遊戲體驗。Cozy Game 強調的是「療癒感」——沒有死亡懲罰、沒有時間壓力、充滿溫暖的視覺風格與音樂。

> **▶ 代表作品**：*星露谷物語、集合啦！動物森友會、My Time at Sandrock、珊瑚島*

> **★ 設計要點**：Cozy Game 已成為重要的市場區隔，吸引了大量傳統遊戲市場較少觸及的族群。設計時要特別注意「不施加壓力」——即使是溫和的時間限制也可能破壞 Cozy 的氛圍。

# 第三章：戰鬥與動作機制

對於動作遊戲開發者而言，以下機制是設計戰鬥系統的基礎詞彙。這些概念彼此連動，共同構成了遊戲「手感」（Game Feel）的核心——也就是玩家按下按鈕後，從視覺、聽覺、觸覺（手把震動）獲得的綜合回饋體驗。

### 幀數據  `Frame Data`

以「幀」（Frame，在 60FPS 的遊戲中為 1/60 秒，約 0.017 秒。FPS 即 Frames Per Second，每秒幀數）為單位來衡量遊戲中所有動作的時間數據。每個動作都可以拆解為三個階段：啟動幀／前搖（Startup，按下按鍵到攻擊生效的準備時間）、活動幀（Active，攻擊判定實際存在的時間）、恢復幀／後搖（Recovery，攻擊結束後到可以再次行動的僵硬時間）。幀數據是所有動作遊戲機制的數學基礎。華語遊戲圈通常把「啟動幀」口語化為「前搖」、把「恢復幀」口語化為「後搖」，讀者會兩種說法都遇到。

> **▶ 代表作品**：*格鬥遊戲如快打旋風、鐵拳；魂系遊戲；魔物獵人*

> **★ 設計要點**：設計動作時，每個招式的幀數據都應該被明確定義在設計文件中。基本原則：快速攻擊＝短啟動幀＋低傷害＋短恢復幀，重攻擊＝長啟動幀＋高傷害＋長恢復幀。這個風險與回報的取捨是平衡性的基礎。

### 硬直  `Hitstun / Hit Recovery`

角色被擊中後的僵硬狀態，在此期間無法執行任何操作。「硬直」一詞源自日文遊戲用語，是動作遊戲中最基本且最重要的機制之一。硬直的長度決定了遊戲是否能形成連段（Combo）——核心公式是：如果敵人的硬直時間大於我方下一次攻擊的啟動幀，就能在敵人恢復之前再次命中，形成連擊。硬直時間＝0 則代表敵人被打到完全不會有反應，像打在棉花上。

> **▶ 代表作品**：*格鬥遊戲、惡魔獵人、魔物獵人、黑暗靈魂*

> **★ 設計要點**：硬直時間設定過長會讓被擊方完全無法反抗（感到無力），過短則讓攻擊沒有重量感（像在搔癢）。建議根據遊戲類型調整：格鬥遊戲需要精確到每一幀的硬直數據，動作 RPG 則可以更寬鬆。

### 無敵幀  `I-Frame / Invincibility Frame`

角色在執行特定動作（如翻滾、墊步、後跳）時獲得的短暫無敵時間。在無敵幀期間，任何攻擊穿過角色身體都不會造成傷害——角色的受擊判定暫時消失。這是《黑暗靈魂》系列中翻滾閃避的核心機制：翻滾動作的中段有數幀的無敵時間，熟練的玩家可以「穿過」敵人的攻擊。無敵幀的長度可以作為難度調節的參數——幀數越多越容易閃避，越少越需要精確的時機掌握。

> **▶ 代表作品**：*黑暗靈魂系列、魔物獵人、魔兵驚天錄、尼爾：自動人形*

> **★ 設計要點**：無敵幀的設計要「感覺得到」——玩家必須透過練習才能掌握時機。建議在開發初期就加入 Debug 模式下的視覺化工具（例如無敵時角色閃爍或變色）來驗證幀數設定。

### 取消  `Cancel / Animation Cancel`

在動作的過程中插入另一個動作來中斷當前動畫。常見的類型包括：跳躍取消（Jump Cancel，用跳躍中斷攻擊恢復幀）、翻滾取消（Dodge Cancel，用翻滾中斷任何動作）、必殺取消（Special Cancel，用特殊技中斷普通攻擊）。取消機制極大地擴展了戰鬥深度——它讓高手玩家能跳過恢復幀，將原本不可能串連的動作組合在一起，創造出華麗的連段。

> **▶ 代表作品**：*惡魔獵人系列、格鬥遊戲、空洞騎士、尼爾：自動人形*

> **★ 設計要點**：取消機制是提高遊戲技術上限的重要工具。但要注意「可發現性」——如果玩家不知道取消的存在，它就沒有意義。建議透過教學關卡或技能說明讓玩家知道這個系統的存在，進階技巧則留給玩家自行發掘。

### 彈反／格擋  `Parry / Deflect / Just Guard`

在敵人攻擊命中的瞬間執行防禦操作，可以完美擋開攻擊並獲得反擊機會。「彈反窗口」（Parry Window）指的是判定成功彈反的時間範圍，通常只有 3 至 10 幀（約 0.05 至 0.17 秒）。近年來彈反機制已成為動作遊戲中最受歡迎的機制之一。《隻狼》的「彈刀」系統將此機制推向了新的高度——遊戲中幾乎所有攻擊都需要透過彈反來應對，彈反成為核心戰鬥節奏而非只是額外選項。

> **▶ 代表作品**：*隻狼：暗影雙死、黑神話：悟空、快打旋風 6、戰神：諸神黃昏*

> **★ 設計要點**：彈反窗口的大小決定了難度。建議設計分層獎勵：「普通格擋」窗口較大但獎勵少（減少傷害），「完美格擋」窗口極小但獎勵大（完全無傷並可反擊），讓不同程度的玩家都有成就感。

### 超級裝甲／霸體  `Super Armor / Hyper Armor`

角色在執行特定動作時獲得的「不會被擊退或擊飛」狀態。受到攻擊仍會扣血，但不會被中斷當前動作（不會產生硬直）。這讓重型武器或特殊技能能夠「硬吃」對方的攻擊並完成出招。在對戰遊戲中，這創造了獨特的策略維度：重型角色可以選擇「用血量換取攻擊機會」。與「韌性」（Poise）概念相近，見後續條目。

> **▶ 代表作品**：*魔物獵人系列、黑暗靈魂、艾爾登法環、榮耀戰魂*

> **★ 設計要點**：霸體讓不同武器類型有了截然不同的戰術風格——輕武器靠閃避與速度取勝，重武器靠霸體硬剛。設計時要注意霸體不應該是無條件的，通常只在特定招式的特定幀數內生效。

### 韌性  `Poise`

角色抵抗被小攻擊中斷的屬性值。與霸體（Super Armor）不同的是，霸體是「特定招式的特定幀數內無敵於中斷」，韌性則是「持續存在、但會被大招耗盡的數值」。在黑暗靈魂系列中，重裝角色的高韌性讓小兵的輕攻擊無法打斷他的重擊揮砍；但對上 Boss 的重擊則韌性會被一擊清空並進入硬直。

> **▶ 代表作品**：*黑暗靈魂系列、艾爾登法環、怪物獵人*

> **★ 設計要點**：韌性讓「重裝 vs 輕裝」的取捨有意義——重裝緩慢但不易被騷擾，輕裝靈活但一被擊中就破招。數值設定時要確保沒有「無敵重裝」（永遠打不斷），也不能讓韌性失去感覺（每招都能打斷）。

### 架勢條／體幹條  `Posture / Stance Bar`

部分現代動作遊戲在血量之外加入的第二資源條。玩家不只可以靠砍血擊敗敵人，也可以透過攻擊、彈反、重擊持續累積對方的架勢值，架勢條滿後敵人會陷入「失衡」（Break/Stagger）狀態，此時可以進行高傷害的「處決」。這個機制最著名的應用是《隻狼》——Boss 的血量極厚，直接砍血幾乎不可能贏，必須透過不斷彈反對手的攻擊累積架勢值，在失衡瞬間處決才能獲勝。

> **▶ 代表作品**：*隻狼：暗影雙死、P 的謊言、黑神話：悟空、魔物獵人的「疲勞值」是類似概念*

> **★ 設計要點**：架勢條把戰鬥從「血量賽跑」變成「節奏博弈」，強迫玩家主動出擊而非消極閃避。設計時要讓架勢值有清楚的視覺呈現（Boss 頭上有第二條條或閃爍特效），否則玩家會搞不懂「為什麼自己明明沒砍到血卻贏了」。

### 蓄力攻擊  `Charged Attack`

按住攻擊鍵一段時間後釋放，可以施放出傷害更高或有特殊效果的強化版攻擊。蓄力期間角色通常處於無法移動或防禦的狀態，形成「高風險高報酬」的取捨。設計精妙的蓄力系統會有多段蓄力（蓄力 1 秒一種效果、2 秒更強、3 秒全滿），或是「完美蓄力」（在特定時間點釋放能獲得最高傷害）。

> **▶ 代表作品**：*魔物獵人的大劍、艾爾登法環的重擊、任天堂明星大亂鬥的蓄力攻擊、Dead Cells*

> **★ 設計要點**：蓄力攻擊的設計挑戰是「讓玩家願意冒這個險」。如果普攻的 DPS 已經很夠，蓄力就變成多此一舉。關鍵是讓蓄力滿的一擊具備「普攻三下的總傷害」或「普攻打不到的破防效果」，創造質變而非量變。

### 暴擊／爆擊  `Critical Hit`

有機率觸發的高額傷害一擊，通常伴隨特殊視覺效果（血液飛濺、畫面閃光、傷害數字放大）與音效強調。暴擊系統由兩個主要屬性構成：暴擊率（Critical Rate，觸發機率）與暴擊傷害（Critical Damage，觸發時的傷害倍率）。玩家在配裝時經常需要在兩者之間取捨——是追求每次都暴擊但倍率普通，還是偶爾暴擊但一擊斃命？暴擊系統源自桌上角色扮演遊戲的「擲骰大成功」傳統，現已是幾乎所有 RPG 與動作遊戲的標配。

> **▶ 代表作品**：*暗黑破壞神系列、原神、艾爾登法環、寶可夢系列、魔物獵人*

> **★ 設計要點**：暴擊的視覺與聽覺回饋要夠誇張——同樣是 1000 點傷害，有暴擊光效和沒有的「爽度」天差地別。部分遊戲（如《絕地戰兵 2》）甚至把爆擊做成玩家追求的核心循環。

### 打擊停頓  `Hitstop / Hit Freeze`

攻擊命中時遊戲短暫停頓的效果，通常只有 2 至 6 幀（約 0.03 至 0.1 秒）。這個極短的停頓讓大腦有時間「註冊」這次命中，配合鏡頭震動（Screen Shake）、粒子特效、音效，共同構成了所謂的「遊戲果汁」（Game Juice）——讓遊戲操作起來充滿回饋感與爽快感的所有微小細節的總和。沒有 Game Juice 的遊戲會讓人感覺在打空氣。

> **▶ 代表作品**：*用於幾乎所有優秀的動作遊戲*

> **★ 設計要點**：Hitstop 是成本最低但效果最明顯的 Game Juice 要素。即使是簡單的 2D 遊戲，加入 3 幀的 Hitstop ＋輕微的鏡頭震動＋命中粒子特效，手感就會有質的飛躍。強烈建議在開發早期就加入這些元素。

### 判定框  `Hitbox / Hurtbox`

Hitbox（攻擊判定框）是招式動作中實際造成傷害的隱形區域，Hurtbox（受擊判定框）是角色身上可被擊中的隱形區域。當 Hitbox 與 Hurtbox 在同一幀重疊時，系統即判定為「命中」。這兩個框的大小、形狀、位置、出現時機與持續時間直接決定了遊戲的手感與公平性。在格鬥遊戲中，判定框的設計是最核心且最耗時的工作之一——每一個招式的每一幀都需要手動調整。

> **▶ 代表作品**：*所有動作遊戲*

> **★ 設計要點**：建議在開發時製作判定框視覺化工具（Debug 模式下用不同顏色顯示 Hitbox 與 Hurtbox）。「看起來打到了卻沒有傷害」或「明明沒碰到卻受傷了」是最容易讓玩家不滿的體驗——判定必須與動畫的視覺表現一致。

### 輸入緩衝  `Input Buffer`

遊戲允許玩家在當前動作尚未結束時就預先輸入下一個指令的機制。系統會將這個提前輸入的指令「暫存」起來，在當前動作結束的瞬間立即執行。緩衝窗口（Buffer Window）指的是系統接受預輸入的時間範圍，通常在 5 至 15 幀之間。這讓遊戲操作更流暢，大幅減少「我明明按了但沒有反應」的挫折感。

> **▶ 代表作品**：*幾乎所有動作遊戲*

> **★ 設計要點**：緩衝窗口過大會讓玩家覺得「角色有自己的意志」（按了一下翻滾，結果角色在一秒後才翻滾），過小則讓操作感覺生硬。建議在 6 至 10 幀之間找到平衡點，並提供選項讓進階玩家自行調整。

### 受身  `Tech / Ukemi`

角色在被擊飛或倒地後的恢復動作。玩家可以在特定時機（通常是接觸地面的瞬間）輸入指令來快速恢復站立姿勢，縮短倒地時間並選擇恢復方向，減少被追擊的風險。「受身」一詞來自日文柔道用語「受け身」（うけみ），指安全跌倒後迅速恢復的技術。

> **▶ 代表作品**：*任天堂明星大亂鬥、格鬥遊戲、魔物獵人*

> **★ 設計要點**：受身機制給了被動方「主動選擇」的機會——向左受身或向右受身會決定後續的戰況發展，避免被單方面控制的無力感。

### 連段  `Combo`

將多個攻擊或技能串連成一個對手無法逃脫的攻擊序列。連段的存在讓動作遊戲有了技術深度與自我表現空間。從簡單的「輕攻擊×3→重攻擊」到複雜的「地面連段→浮空技（將敵人擊飛到空中的招式）→空中連段→壁彈（敵人撞到牆後彈回）→再追擊→終結技」，不同遊戲的連段複雜度差異極大。連段的傷害通常會隨著 Hit 數遞減（稱為「傷害修正」Damage Scaling），避免一套連段直接秒殺對手。

> **▶ 代表作品**：*惡魔獵人、格鬥遊戲、空洞騎士、尼爾：自動人形*

> **★ 設計要點**：好的連段設計要有「層次」——基礎連段（3 至 4Hit）讓新手可以上手，進階連段（7 至 10Hit 以上）讓高手有發揮空間。設計時也要考慮「被連段的一方」的體驗，過長的連段會讓對手感到無聊。

### 投技  `Throw / Command Grab`

格鬥與動作遊戲中跳過防禦、直接抓住對手造成傷害的技能。投技是「三竦」（石頭剪刀布式的平衡）結構的關鍵——攻擊擊敗投技（因為你打到要抓人的對手）、防禦擊敗攻擊（擋住）、投技擊敗防禦（抓住龜縮的對手）。沒有投技的格鬥遊戲會變成「大家一直蹲著防」的僵局。現代動作遊戲的「處決技」「環境互動」也常是投技的變體。

> **▶ 代表作品**：*快打旋風系列、鐵拳系列、任天堂明星大亂鬥、黑暗靈魂的爬蟲處決*

> **★ 設計要點**：投技的視覺效果要夠誇張——玩家通常把投技視為「羞辱性擊敗」，演出越有破壞性越能帶來爽快感。範例：《快打旋風 6》的紮基爾投技演出幾乎是慢動作特寫。

### 冷卻時間  `Cooldown (CD)`

技能或道具使用後必須等待才能再次使用的時間，是遊戲平衡最常用的工具之一。有了冷卻時間，強力技能才能「又強又公平」——一招能打掉對方一半血的大絕招，如果 3 秒冷卻一次就破壞遊戲；如果 60 秒冷卻一次就能成為關鍵決策點。冷卻時間通常從技能施放瞬間開始計算，部分設計會有變體：全球冷卻（Global Cooldown, GCD，按任何技能後短時間內都不能用其他技能）、共享冷卻（某一類技能共用一個冷卻）、層數式（如維斯塔拉斯有 3 層技能，每次用掉一層）等。

> **▶ 代表作品**：*所有 MOBA、MMO、技能導向的動作遊戲都依賴 CD 平衡*

> **★ 設計要點**：CD 的設計原則：「使用頻率」決定技能的定位——短 CD 用於日常輸出、長 CD 用於關鍵時機。最忌讓「最強技能同時 CD 最短」。UI 上技能圖示的冷卻顯示（扇形填充、數字倒數）是玩家每秒都在看的資訊，視覺回饋必須清晰。

### 吟唱／施法時間  `Cast Time`

施放技能前的詠唱／蓄力時間。與「前搖」類似但更常用於魔法或遠程技能語境。吟唱期間玩家通常無法移動或攻擊，且許多遊戲允許敵人透過特定技能「打斷吟唱」（Interrupt）——這產生了額外的戰術層次：要不要保留一個中斷技能來打斷對方的關鍵施法？

> **▶ 代表作品**：*魔獸世界、Final Fantasy XIV、暗黑破壞神、英雄聯盟*

> **★ 設計要點**：吟唱時間的設計是「威力 vs 風險」的直接對應——越強的技能吟唱越長，給對手的反應時間也越長。近戰職業通常吟唱短或不吟唱，法系職業吟唱長但威力高，這是職業差異化的基礎。

### 範圍攻擊  `Area of Effect (AOE)`

一次影響多個目標的攻擊或效果。形狀常見有：圓形（以施法者或目標為圓心）、扇形（像劍客的橫掃）、直線（閃電鏈、穿透箭）、矩形（地毯式轟炸）等。AOE 是對付敵群最有效的手段，但通常傷害比單體技能低（以面積換強度）。部分遊戲有「友傷」（Friendly Fire，AOE 也會傷到隊友）機制，讓 AOE 釋放需要更謹慎。

> **▶ 代表作品**：*暗黑破壞神系列、英雄聯盟、魔物獵人、絕地戰兵 2*

> **★ 設計要點**：AOE 的施放指示（Telegraph）對 PvE 與 PvP 都極重要——玩家必須能清楚看到「攻擊會落在哪裡」才能閃避。業界標準做法是地面上出現紅色預警區域，在技能落下前數秒顯示。

### 仇恨值／威脅值  `Aggro / Threat / Enmity`

在多人遊戲或有 AI 隊友的遊戲中，決定敵人優先攻擊誰的隱藏數值系統。坦克（Tank）角色透過特定嘲諷技能或持續攻擊來累積仇恨值，讓 Boss 專注攻擊自己，保護負責輸出傷害（DPS）或治療（Healer）的隊友。這是「聖三位一體」（Holy Trinity：Tank-DPS-Healer，源自西方 MMO 的團隊分工設計）的數學基礎——坦克承受、輸出造傷、治療回血，三者缺一不可。

> **▶ 代表作品**：*大型多人線上角色扮演遊戲如 Final Fantasy XIV、魔獸世界；部分動作角色扮演遊戲*

> **★ 設計要點**：仇恨值的計算公式直接影響團隊配合的深度。基本設計：治療行為產生的仇恨＝治療量×仇恨係數，攻擊產生的仇恨＝傷害量×仇恨係數。坦克的嘲諷技能則直接將仇恨值拉到最高。

### 增益／減益  `Buff / Debuff`

暫時提升（Buff）或降低（Debuff）角色屬性的效果。Buff 的例子如：攻擊力提升 30% 持續 10 秒、移動速度加快、護盾吸收一定傷害。Debuff 的例子如：速度降低 50%、防禦力下降、持續掉血（即 DOT）。增益／減益系統讓戰鬥不僅是比拼基礎數值，還增加了「狀態管理」的策略層次——何時施加、何時解除、優先消除哪個減益都是重要決策。注意：Buff 在版本更新語境下則是動詞，意為「把某東西調強」，與這裡的「增益狀態」是同字雙義。

> **▶ 代表作品**：*幾乎所有角色扮演與動作遊戲*

> **★ 設計要點**：增益／減益的視覺回饋極為重要——玩家必須能一眼看出當前身上有哪些效果、還剩多少時間。建議使用統一的圖示系統，Buff 在角色上方、Debuff 在下方，搭配倒數計時器與顏色標示。

### 群體控制  `Crowd Control (CC)`

使敵人失去部分或全部行動能力的效果統稱。常見的 CC 類型包括：暈眩（Stun，完全無法行動）、冰凍（Freeze，無法移動與攻擊）、擊飛（Knockback，被推離原位）、沉默（Silence，無法使用技能但可以移動和普攻）、定身（Root，無法移動但可以攻擊）、催眠（Sleep，無法行動但受到傷害會解除）。CC 能力在 PvP 中尤其強大，往往是決定勝負的關鍵。

> **▶ 代表作品**：*多人線上戰鬥競技場（MOBA）如英雄聯盟、Dota 2；大型多人線上角色扮演遊戲*

> **★ 設計要點**：CC 的設計要避免「無限 CC 鏈」——玩家被連續控制十幾秒完全無法操作是最糟糕的遊戲體驗。建議加入「遞減效果」（Diminishing Returns）機制：連續受到同類 CC 時，效果持續時間逐次縮短，最終短暫免疫。

### 持續傷害  `DOT (Damage Over Time)`

在一段時間內持續造成傷害的效果，常見的表現形式包括中毒（持續扣血）、燃燒（火焰傷害）、流血（物理持續傷害）。與「直接傷害」（Burst Damage，一次性造成大量傷害）相對。DOT 的總傷害通常更高，但因為分散在數秒甚至數十秒內，不會立即致命，適合消耗型的持久戰術。在部分遊戲中 DOT 可以疊加，多層中毒的傷害遠超單層。

> **▶ 代表作品**：*艾爾登法環的紅腐與劇毒、英雄聯盟、暗黑破壞神系列*

> **★ 設計要點**：DOT 設計要讓玩家能明確感知自己正在受到持續傷害（螢幕邊緣泛紅、角色動作異常等），並提供應對手段（解毒藥、等待消散、特定技能清除等）。

# 第四章：遊戲系統與機制設計

遊戲系統是支撐遊戲體驗的骨架。從經濟系統到進度系統，每個設計決策都會影響玩家的行為模式。

### 遊戲即服務  `GaaS (Games as a Service)`

遊戲不再是買斷式的單次性產品，而是持續營運的線上服務。遊戲上線後，開發團隊持續更新內容（新角色、新地圖、新劇情）、推出限時季節活動、販售虛擬物品（造型、外觀）來維持長期營收。通常採用「免費遊玩＋內購」（Free-to-Play, F2P）或「買斷＋季票」的商業模式。這已成為現代遊戲產業的主流，但也引發了關於「玩家是否真正擁有自己的遊戲」與「遊戲停止營運後內容消失」的討論。

> **▶ 代表作品**：*要塞英雄、天命 2、原神、Apex 英雄、Final Fantasy XIV*

> **★ 設計要點**：GaaS 模式要求持續的內容開發能力與穩定的伺服器維運。小團隊應慎重評估是否有足夠資源支撐長期營運。業界有許多 GaaS 失敗案例（如 Anthem、Babylon's Fall、Concord），證明光有 3A 品質不夠，還需要長期的內容規劃。

### 戰鬥通行證  `Battle Pass`

以「季節」（通常 2 至 3 個月）為週期的獎勵路徑系統。玩家透過完成每日／每週任務獲得經驗值，經驗值累積後逐步解鎖路徑上的獎勵。通常分為免費路徑（所有玩家可用）與付費路徑（需購買通行證，獎勵更豐富）。這種設計的心理機制在於「沉沒成本」——已經買了通行證的玩家會更積極地遊玩以「值回票價」。

> **▶ 代表作品**：*要塞英雄、Apex 英雄、特戰英豪、幾乎所有 GaaS 遊戲*

> **★ 設計要點**：設計要讓玩家感到「值得」而不是「被迫」。避免過度的 FOMO（Fear of Missing Out，俗稱「怕錯過症」，行銷常用的心理機制）設計——如果玩家覺得自己必須每天上線否則就會錯過限定獎勵，這份壓力會慢慢轉變為厭倦。部分遊戲已開始允許補完過去賽季的通行證。

### 轉蛋／抽卡  `Gacha`

來自日本扭蛋機（ガチャ）的隨機抽取機制。玩家花費虛擬貨幣（可用真實金錢購買）來進行隨機抽取，有機率獲得不同稀有度的角色、武器或物品。「保底機制」（Pity System）是指在連續若干次未抽到最高稀有度物品後，系統保證下一次必定獲得——例如原神的 90 抽保底機制。轉蛋機制利用了「可變比率增強」（Variable Ratio Reinforcement）的心理學原理，與老虎機相同，是最容易引發成癮行為的獎勵模式。

> **▶ 代表作品**：*原神、Fate/Grand Order、明日方舟、蒼藍檔案、鳴潮*

> **★ 設計要點**：設計轉蛋時必須考慮：保底機制（多少抽必出最高稀有度）、機率透明度（各國法規日趨嚴格，許多國家要求公開掉率）、非付費玩家的體驗（確保不花錢也能正常遊玩）。過度依賴轉蛋獲利會傷害遊戲口碑與長期壽命。

### Meta／最佳策略  `Meta / Metagame`

在競爭性遊戲中，當前被認為最有效率的策略、角色選擇或裝備配置。Meta 是「Most Effective Tactics Available」（當前最有效戰術）的縮寫。Meta 會隨著版本更新、職業技能調整（稱為「改版」或「Patch」）、以及玩家社群發現新戰術而不斷變化。「跟 Meta」意味使用當前公認最強的配置，「反 Meta」則是挑戰主流的非常規策略——用 Meta 的弱點來反制它。在版本更新的語境下，Nerf 指削弱、Buff 指增強；玩家常說「這個角色被 Nerf 了」「下個版本要 Buff 法師」等。

> **▶ 代表作品**：*英雄聯盟、特戰英豪、遊戲王、寶可夢*

> **★ 設計要點**：健康的 Meta 應該有多個可行策略而非單一最優解（即「Meta 多樣性」）。定期調整平衡性以保持 Meta 活力是 GaaS 遊戲營運團隊最重要的日常工作之一。

### Build／配裝  `Build / Character Build`

玩家為角色選擇的技能、裝備、屬性點數、符文等的整體組合方案。一個好的 Build 系統讓玩家能根據自己的遊玩風格打造獨特的角色——有人喜歡全攻擊的「玻璃砲」，有人偏好高防禦的「鐵壁」。「Min-Max」則指極限化配裝的行為，將某一項屬性推到極致同時完全放棄其他屬性，追求最高理論效率。

> **▶ 代表作品**：*暗黑破壞神系列、流亡黯道、艾爾登法環、原神*

> **★ 設計要點**：Build 多樣性是 RPG 重玩價值的來源。設計時要確保多種 Build 都有可行性，而不是只有一種「正確」配置。如果所有玩家最終都選擇相同的 Build，代表系統的平衡性出了問題。

### 技能樹／天賦樹  `Skill Tree / Talent Tree`

以樹狀或網狀結構呈現的角色成長系統。玩家每次升級獲得的「技能點」可以投資到樹上的節點，解鎖新技能或強化被動能力。不同的投點路徑會塑造出截然不同的遊玩風格。《流亡黯道》的巨大網狀天賦樹（超過 1,300 個節點）是最極端的例子。

> **▶ 代表作品**：*流亡黯道、暗黑破壞神 4、邊緣禁地系列*

> **★ 設計要點**：避免「假選擇」——每個節點都應該對遊玩有可感知的影響。「+2% 攻擊力」這種微小的數值提升讓人毫無成就感，不如設計「攻擊附帶火焰效果」這類可以改變遊玩方式的節點。

### 稀有度階層  `Rarity Tier`

裝備、角色或物品的品質分級系統，通常以顏色區分。西方 MMO 傳統配色為：白（普通）→綠（罕見）→藍（稀有）→紫（史詩）→橙（傳說），部分遊戲在最高階上再加紅或彩（神話／不朽）。日系手遊則常用 N→R→SR→SSR→UR 的字母階層。稀有度系統讓玩家一眼辨別裝備價值，也是轉蛋與掉寶系統的核心心理鉤子——看到一道紫光或橙光時的興奮感，就是這套系統要製造的。

> **▶ 代表作品**：*暗黑破壞神系列、魔獸世界、原神、邊緣禁地*

> **★ 設計要點**：稀有度的視覺與音效要分層級差異——紫裝掉落的特效要比藍裝誇張、橙裝要比紫裝更加震撼。高階稀有度的掉落應該是「值得停下手邊動作去撿」的體驗，而非一閃而過。

### 合成／鍛造／附魔  `Crafting / Forging / Enchantment`

透過收集材料、消耗資源來製作、強化或改造裝備的系統。合成（Crafting）通常指從零製作新物品；鍛造／強化（Upgrade）是提升現有裝備的數值；附魔（Enchantment）則是為裝備附加特殊效果（例如「攻擊附帶火焰傷害」）。完整的合成系統能讓玩家從「被動接受掉落」轉為「主動追求想要的裝備」，大幅延長遊戲壽命。

> **▶ 代表作品**：*魔物獵人系列、當個創世神、流亡黯道、艾爾登法環、泰拉瑞亞*

> **★ 設計要點**：合成系統最大的陷阱是「稀有材料檻」——如果最終裝備需要的材料過於稀有，玩家會陷入絕望的刷取循環。建議設計多種替代路徑讓玩家選擇，而非單一瓶頸。

### 背包／庫存系統  `Inventory`

玩家攜帶物品的容器系統。設計方式差異極大：有無限容量（《寶可夢》從某作開始）、有數量上限（多數 RPG）、有重量限制（《上古卷軸》系列）、有格子限制（《暗黑破壞神》的九宮格物品佔用不同格數）、有重量＋格子雙限制（《惡靈古堡 4》的行李箱）。背包管理本身就是獨立的設計議題——《惡靈古堡 4》的九宮格行李箱甚至成為遊戲記憶點。

> **▶ 代表作品**：*暗黑破壞神系列、惡靈古堡 4、上古卷軸系列、逃離塔科夫*

> **★ 設計要點**：背包設計的核心問題是：「物品管理」應該是樂趣還是負擔？對 Hardcore RPG 玩家來說，整理背包是成就感；對休閒玩家則是勞役。現代遊戲常提供「自動整理」「快速分解」「倉庫擴充」等功能平衡兩者。

### 存檔點／檢查點  `Save Point / Checkpoint`

玩家可以保存進度或死亡後復活的地點。存檔點系統分多種流派：隨時存檔（PC 遊戲傳統）、僅在存檔點存檔（日式 RPG 傳統，如最終幻想的水晶）、篝火式存檔（黑暗靈魂的篝火，存檔時會重生所有敵人）、自動檢查點（現代遊戲標配，死亡後直接從上一個檢查點復活）。存檔頻率直接影響遊戲壓力——間隔越遠緊張感越高。

> **▶ 代表作品**：*黑暗靈魂的篝火、惡靈古堡的打字機、最終幻想的水晶、所有現代動作遊戲的自動檢查點*

> **★ 設計要點**：檢查點設計的關鍵是「玩家不應該對死亡感到無助」——死亡後重來的內容不能太長。業界經驗：一次死亡後的倒退不應超過 3 至 5 分鐘遊玩時間，否則會累積挫折感。

### 快速旅行  `Fast Travel`

讓玩家從一個地點瞬間移動到另一個已探索地點的系統。開放世界與半開放世界遊戲的標配。設計上有不同取向：完全自由（任何地點直接傳送，如《上古卷軸 5》）、需要傳送點（如《艾爾登法環》的賜福）、需要付費或消耗物品、或是禁用快速旅行以強化世界真實感（《碧血狂殺 2》的極簡設計）。

> **▶ 代表作品**：*上古卷軸 5、艾爾登法環、巫師 3、曠野之息*

> **★ 設計要點**：快速旅行是「便利性」與「世界感」的取捨。太自由讓世界縮小（不再需要探索中間地區），太嚴格會讓玩家覺得在浪費時間。折衷方案：限制為「已探索地點之間」或「需要到特定建築才能使用」。

### 二周目  `New Game Plus (NG+)`

用先前遊玩的角色數據（等級、裝備、技能）重新開始遊戲，但敵人更強或有新內容解鎖。NG+ 提供了重玩的動機，讓玩家能體驗不同選擇、挑戰更高難度、或發現前一周目忽略的內容。部分遊戲的真結局甚至只能在 NG+ 才能觸發。

> **▶ 代表作品**：*黑暗靈魂系列、尼爾：自動人形、女神異聞錄系列、黑帝斯*

> **★ 設計要點**：NG+ 是低成本增加遊戲壽命的有效方式。但要確保新周目有足夠的新元素（新敵人配置、新物品、新劇情分支），而不僅僅是「敵人數值更高」。《尼爾：自動人形》的 NG+ 讓你從不同角色的視角重新體驗故事，是教科書級的設計。

### QTE  `Quick Time Event`

在過場動畫或特定場景中突然要求玩家在限定時間內按下螢幕提示的按鍵。成功則觸發特殊效果或精彩演出，失敗則可能受到傷害、錯過獎勵或導致角色死亡。QTE 在遊戲圈中評價兩極——好的 QTE 如《戰神》的 Boss 終結演出讓玩家覺得自己參與了史詩時刻，差的 QTE 則讓玩家覺得只是在看電影時被迫玩反應測試小遊戲。

> **▶ 代表作品**：*戰神系列、莎木系列、阿修羅之怒、惡靈古堡系列*

> **★ 設計要點**：QTE 的設計原則：按鍵提示要夠大夠明顯、反應時間要合理、失敗後果不能太嚴厲（至少提供重試機會）。最重要的是 QTE 必須與當前劇情情緒匹配——在緊張的追逐戲中按下 QTE 閃避障礙物是好的，在安靜的對話場景中突然跳出 QTE 是糟糕的。

### 成就／獎盃  `Achievement / Trophy`

記錄玩家達成特定目標的虛擬勳章系統。Steam 稱之為「成就」（Achievements），PlayStation 稱為「獎盃」（Trophies，分銅銀金白金四階），Xbox 有「成就點數」（Gamerscore）。成就是最廉價但最有效的延壽工具——讓玩家為了 100% 完成度願意做原本不會做的事（例如用特殊武器通關、收集所有隱藏物品）。白金獎盃（完成一款遊戲所有獎盃）是 PS 玩家的終極勳章。

> **▶ 代表作品**：*所有現代主機與 PC 遊戲*

> **★ 設計要點**：成就設計要平衡「可達成」與「有挑戰」——全部太簡單就像參與獎、全部太難會讓人直接放棄。理想配比：多數成就（70%）是玩正常流程就能自然獲得、部分（25%）需要有意識地去拿、少數（5%）是真正的高手挑戰。

### 彩蛋  `Easter Egg`

開發者藏在遊戲中的隱藏致敬、笑話、秘密訊息，通常與主線內容無關。名稱源自復活節找彩蛋的傳統——需要玩家主動尋找才能發現。經典彩蛋包括：特定動作觸發的隱藏對話、場景中致敬其他作品的物件、開發者自己的照片／留言、或是整個隱藏關卡。1979 年《冒險》（Atari）中藏入設計師名字被視為電玩彩蛋的起源。

> **▶ 代表作品**：*俠盜獵車手系列、刺客教條系列、柏德之門 3、巫師 3*

> **★ 設計要點**：彩蛋是開發團隊與玩家的「私人對話」——好的彩蛋讓發現的玩家感到驚喜並想分享，形成社群話題。設計時要確保彩蛋不影響主要流程（不會被當成 Bug），並且真的需要一點尋找才能發現（太明顯就失去樂趣）。

### 環境敘事  `Environmental Storytelling`

透過遊戲環境中的物件擺放、場景設計、細節元素來傳達敘事的手法。例如：一間空蕩的育嬰室裡有一張倒下的嬰兒床和地上的血跡——不需要任何文字或對話，玩家就能理解這裡發生了什麼。這種「讓玩家自己拼湊真相」的敘事方式比直接告知更具沉浸感與情感衝擊力。

> **▶ 代表作品**：*黑暗靈魂、最後生還者、生化奇兵、回家、戰慄時空：艾莉克斯*

> **★ 設計要點**：環境敘事需要關卡設計、美術、敘事團隊的緊密協作。每個物件的擺放都應該有敘事意圖——角色的日記放在桌上、旁邊是一杯已經冷掉的咖啡和一支翻倒的筆，暗示此人在書寫時被迫匆忙離開。

### 遊戲迴圈／核心迴圈  `Game Loop / Core Loop`

玩家在遊戲中不斷重複的基本行為循環。核心迴圈定義了遊戲「每一輪」的基本流程。例如《魔物獵人》的核心迴圈是「接受任務→準備裝備與道具→出發狩獵→擊敗魔物→獲得素材→製作更強的裝備→挑戰更強的魔物」。核心迴圈的設計好壞直接決定了遊戲是否好玩、是否能讓玩家「再來一次」。

> **▶ 代表作品**：*所有遊戲*

> **★ 設計要點**：設計核心迴圈時要確保「迴圈中的每個步驟都有樂趣」，而不僅是最終結果有樂趣。如果玩家只為了結果而忍耐過程（例如無聊地刷怪只為了拿裝備），代表中間環節的設計出了問題。

### 心流  `Flow State`

由心理學家契克森米哈伊（Mihaly Csikszentmihalyi）提出的概念，指人在完全專注於某項活動時進入的最佳體驗狀態。在遊戲設計中，心流出現在遊戲難度與玩家技能完美匹配時——挑戰太低會無聊（Boredom），挑戰太高會焦慮（Anxiety），只有在中間的「心流通道」（Flow Channel）時玩家才會完全沉浸、忘記時間的流逝。

> **▶ 代表作品**：*所有遊戲設計的基礎理論*

> **★ 設計要點**：設計難度曲線時永遠以心流理論為指導。動態難度調整（DDA）是一種自動化的實現方式——遊戲偷偷根據玩家的表現調整敵人的血量或傷害。《惡靈古堡 4》就有經典的隱性 DDA 系統。

### 動態難度調整  `DDA (Dynamic Difficulty Adjustment)`

遊戲根據玩家當前表現自動調整挑戰強度的系統。表現好的玩家會遇到更強的敵人或更少的補給，表現差的玩家則會感到遊戲「變簡單」。目標是讓所有玩家都停留在心流通道內。DDA 通常是「隱性」的——玩家不應該察覺到遊戲在偷偷調整，否則會覺得遊戲不公平或自己的勝利不值。

> **▶ 代表作品**：*惡靈古堡 4（經典隱性 DDA）、左 4 死 2（AI Director 根據玩家狀態生成事件）、瑪利歐賽車（落後者獲得更好道具）*

> **★ 設計要點**：DDA 的風險是被玩家識破——「我越強敵人越強，那我為什麼要努力？」這是最糟糕的玩家心理。建議 DDA 的調整範圍保守（正負 20% 內），且不影響玩家的核心能力感。

### 隨機數生成器  `RNG (Random Number Generator)`

遊戲中決定所有隨機事件的底層機制，影響掉寶機率、暴擊機率、命中率、隨機事件觸發等。所謂「偽隨機」（Pseudo-random Distribution, PRD），是一種讓隨機結果更「公平」的演算法——每次未觸發時，下一次的觸發機率會逐漸提高。例如一個名義上 25% 機率的暴擊，使用 PRD 後不會出現連續 20 次不暴擊的極端情況。

> **▶ 代表作品**：*所有包含隨機元素的遊戲*

> **★ 設計要點**：過多的 RNG 讓玩家感覺「運氣遊戲」（結果完全取決於運氣而非技術），過少則缺乏驚喜。黃金法則：讓 RNG 影響「如何贏」（掉了什麼裝備決定這局的 Build 方向）而非「是否能贏」（Boss 有 50% 機率放出必殺技直接秒殺你）。

# 第五章：多人遊戲與網路機制

網路多人遊戲已成為遊戲市場的主流。理解多人遊戲的專有名詞對於遊戲企劃與開發都很重要。

### PvP／PvE／PvPvE  `Player vs Player / Player vs Environment`

PvP（玩家對玩家）指玩家之間的直接對抗，PvE（玩家對環境）指玩家對抗電腦控制的敵人，PvPvE 則是兩者的結合——玩家在對抗 AI 敵人（如殭屍、怪物）的同時也要提防其他真人玩家。PvPvE 是近年的熱門設計趨勢，尤其在抽取式射擊遊戲中——你可能正在專心打 Boss，結果背後被另一組玩家偷襲。

> **▶ 代表作品**：*天命 2、全境封鎖、暗與暗、獵殺：對決*

> **★ 設計要點**：PvPvE 的設計挑戰在於平衡 PvP 與 PvE 的比重。如果 PvE 敵人太弱，遊戲就只是 PvP；如果 PvE 太強，玩家會因為忙著對付 AI 而無暇顧及其他玩家，失去 PvPvE 的張力。

### 協力／對戰模式  `Co-op / Versus`

Co-op（Cooperative，協力）是多名玩家共同對抗電腦或解決挑戰的合作模式；Versus（對戰）則是玩家彼此對抗。部分遊戲同時提供兩種模式以擴大受眾。協力模式的設計核心是「每個玩家都有重要角色」——好的協力遊戲讓隊友合作比單打獨鬥快，而不只是多一個人幫忙打而已。

> **▶ 代表作品**：*It Takes Two、絕地戰兵 2、怪獵系列、Left 4 Dead 2、分裂小隊*

> **★ 設計要點**：協力模式的失敗案例往往是「一個人帶三個廢物」——核心玩家承擔所有事，其他隊友只能跟班。設計時要確保每個位置都有獨特貢獻（例如治療職只有他能救人、坦克職只有他能嘲諷）。

### 技能配對  `SBMM (Skill-Based Matchmaking)`

根據玩家的技術水平（通常使用隱藏的 MMR 分數，即 Matchmaking Rating）進行配對的系統，確保玩家與實力相近的對手競爭。SBMM 是遊戲社群中最具爭議的話題之一——支持者認為它保護新手不被高手虐殺，反對者認為它讓每場遊戲都像在「上班」（因為永遠遇到同等級的對手，無法輕鬆地碾壓或放鬆遊玩）。

> **▶ 代表作品**：*要塞英雄、決勝時刻系列、Apex 英雄*

> **★ 設計要點**：SBMM 的強度是關鍵設計決策。太強的 SBMM 讓高手玩家永遠無法享受輕鬆的一局，太弱則讓新手被虐殺後離開遊戲。部分遊戲採用折衷方案——休閒模式降低 SBMM 強度，排位模式則嚴格配對。

### 延遲／Ping  `Latency / Ping`

資料從玩家電腦傳送到伺服器再回來所花的時間，以毫秒（ms）為單位。Ping 值越低操作越即時——30ms 以下近乎感覺不到、60ms 內可接受、100ms 以上開始感到「頓」、200ms 以上幾乎無法進行競技遊戲。Ping 受物理距離限制（光速在網路電纜中傳遞也需要時間），因此遊戲會在世界各地設置「伺服器區」（Server Region）讓玩家連最近的機房。與 Ping 相關的概念還有：封包遺失（Packet Loss，資料包在傳輸中丟失）、抖動（Jitter，Ping 值不穩定地跳動）。

> **▶ 代表作品**：*所有線上遊戲都受這些指標影響*

> **★ 設計要點**：面向競技的遊戲應顯示即時 Ping 值讓玩家了解狀況。Ping 過高時應給予明確提示與建議（例如「您的連線不穩，建議切換至亞洲伺服器」），而非讓玩家困惑為什麼自己打不中人。

### 回滾網路碼  `Rollback Netcode`

一種先進的網路同步技術。運作原理：本地端先假設遠端玩家會繼續執行上一幀相同的操作，並據此繼續模擬遊戲；等到遠端玩家的實際操作資料到達後，如果預測正確就繼續，如果預測錯誤則「回滾」到上一個確認狀態並快速重新模擬到當前幀。相較於傳統的延遲型網路碼（Delay-based Netcode，等待雙方資料都到達後才推進遊戲），回滾網路碼能在高延遲環境下仍然提供流暢的操作體驗。近年來已成為格鬥遊戲的標準配備。

> **▶ 代表作品**：*快打旋風 6、聖騎士 Strive、鐵拳 8、蒼翼默示錄*

> **★ 設計要點**：對於任何包含 PvP 的遊戲，網路技術的選擇直接影響玩家體驗。回滾網路碼的實作難度較高，但玩家體驗遠優於延遲型方案。開源函式庫 GGPO（一套廣泛使用的回滾網路碼程式庫）是常見的起點。

### 反外掛  `Anti-cheat`

偵測並阻止玩家使用外掛程式的系統。常見外掛類型：自動瞄準（Aimbot）、透視牆壁（Wallhack）、無後座力、自動完美操作等。反外掛分兩大派系：使用者模式（運行在遊戲本身的權限，較弱但無隱私疑慮）與核心模式（深入作業系統核心，如 Valorant 的 Vanguard、決勝時刻的 Ricochet，有效但引發隱私爭議）。反外掛是線上競技遊戲的生死線——一款遊戲被判定「滿街外掛」後很快會失去玩家。

> **▶ 代表作品**：*Easy Anti-Cheat（EAC）、VAC（Valve Anti-Cheat）、Vanguard、Ricochet、nProtect GameGuard*

> **★ 設計要點**：反外掛必須與遊戲一起從第一天規劃，不能後補。外掛者永遠在進化，因此反外掛需要持續更新。建議同時投資「伺服器端偵測」（透過統計異常識別外掛者）與「回報系統」（讓玩家舉報可疑行為）。

### 大廳／房間系統  `Lobby / Room System`

玩家在遊戲開始前的等待與組織區域。典型功能包括：公開大廳列表（Browser）、私人房間（Private Room）、好友邀請、快速配對（Quick Match）、角色選擇、地圖投票等。大廳設計直接影響「開一局遊戲有多麻煩」——過繁瑣的大廳會讓玩家放棄配對。

> **▶ 代表作品**：*幾乎所有多人遊戲*

> **★ 設計要點**：現代趨勢是「無縫配對」（Seamless Matchmaking）——玩家按一顆按鈕就進入遊戲，不需要手動設定。但對於有複雜設定需求的遊戲（如自訂規則、指定地圖），完整的房間系統仍有必要。

### 跨平台遊玩  `Cross-play / Cross-platform`

不同平台（PC、PlayStation、Xbox、Nintendo Switch、手機）的玩家可以在同一個伺服器一起遊玩的功能。跨平台遊玩對於維持線上遊戲的玩家數量至關重要——避免每個平台的玩家池過小導致配對時間過長。跨平台存檔（Cross-save）則是讓玩家在不同平台間共用遊戲進度的功能。

> **▶ 代表作品**：*要塞英雄、火箭聯盟、Final Fantasy XIV、原神*

> **★ 設計要點**：跨平台需要考慮輸入設備的公平性——鍵盤滑鼠在射擊遊戲中的瞄準精度遠高於手把。常見解法是允許玩家選擇「只與相同輸入設備配對」。各平台廠商的政策限制（如帳號系統互通、商店分潤）也是實務上的挑戰。

### 非同步多人  `Asynchronous Multiplayer`

玩家不需要同時在線即可互動的多人機制。玩家 A 的遊戲行為（留言、紀錄、建造物等）會被伺服器儲存，並在玩家 B 遊玩時出現在其世界中。《黑暗靈魂》的血跡與幻影系統是經典範例——玩家可以看到其他玩家死亡的地點（紅色血跡）和臨終前的幽靈動畫，還能在地上留下文字訊息警告或誤導其他玩家，創造出「孤獨卻不孤單」的獨特體驗。

> **▶ 代表作品**：*黑暗靈魂系列、死亡擱淺、超級瑪利歐創作家*

> **★ 設計要點**：非同步多人的開發成本與技術門檻遠低於即時多人（不需要處理網路同步問題），卻能提供強大的社群連結感。非常適合獨立開發者採用。

# 第六章：技術與圖形

現世代遊戲的技術發展日新月異。理解這些技術不僅是工程師的專業，對企劃與美術也影響深遠——因為它們決定了你的遊戲可以「做什麼樣的畫面」「跑在什麼樣的硬體上」。本章涵蓋從基礎的光柵化到 2026 年最新的 DLSS 5 神經渲染技術。

### 遊戲引擎  `Game Engine`

提供遊戲開發所需的核心技術框架與工具集的軟體平台。引擎整合了渲染、物理、動畫、音訊、AI、網路、腳本、編輯器等系統，讓開發者可以專注在遊戲設計本身而非從頭寫基礎設施。主流商用引擎包括 Unity（跨平台友善、中小型團隊的首選、以 C# 為腳本語言）、Unreal Engine（畫質強大、3A 首選、以 C++ 與藍圖視覺化腳本為主）、Godot（開源免費、輕量、適合 2D 與獨立遊戲）。自製引擎（In-house Engine）如 CAPCOM 的 RE Engine、FromSoftware 的自製引擎則針對自家遊戲特性深度最佳化。

> **▶ 代表作品**：*Unity：原神、爐石戰記、Among Us；Unreal：絕地求生、黑神話：悟空、要塞英雄；Godot：Brotato、Cassette Beasts*

> **★ 設計要點**：引擎選擇沒有絕對最佳——取決於團隊規模、專案類型、成員經驗、授權預算。教學建議：學生先學 Unity（入門門檻最低、教材最豐富），再視需求擴展到 Unreal。引擎是工具不是信仰，不同專案可以用不同引擎。

### 光柵化  `Rasterization`

傳統的即時 3D 渲染技術，也是過去三十年來遊戲畫面的基礎。基本原理：將 3D 空間中的三角形投影到 2D 螢幕平面，再逐一計算每個像素的顏色。光柵化的優點是「快」——現代 GPU 每秒能處理數十億個三角形；缺點是光影效果必須靠各種「近似技巧」（陰影貼圖、環境光遮蔽、立方體反射貼圖等）拼湊出來，而這些技巧都有其限制（例如傳統陰影貼圖的鋸齒、反射只能做水面這類平面）。2018 年光線追蹤硬體出現後，遊戲畫面開始從「光柵化為主」轉向「光柵化＋光線追蹤混合」。

> **▶ 代表作品**：*幾乎所有 2018 年以前的遊戲都是純光柵化*

> **★ 設計要點**：即使在光線追蹤時代，光柵化仍是效能的基礎。學生學習 3D 圖學時應先掌握光柵化的原理（頂點著色、像素著色、深度測試、模板測試等），這是理解所有進階技術的基礎。

### 著色器  `Shader`

在 GPU 上執行的小程式，負責計算畫面上每個像素的最終顏色。主要類型：頂點著色器（Vertex Shader，處理每個頂點的位置與屬性）、片段／像素著色器（Fragment/Pixel Shader，處理每個像素的顏色計算）、計算著色器（Compute Shader，用於通用平行計算如粒子、流體模擬）。材質的質感（金屬、布料、皮膚）、特效（火焰、煙霧、水）、後處理（景深、動態模糊、色調映射）全都由 Shader 實現。著色器語言主流為 HLSL（DirectX）與 GLSL（OpenGL / Vulkan），Unity 有自家的 ShaderLab，Unreal 則可用材質編輯器以節點視覺化建構 Shader。

> **▶ 代表作品**：*所有現代 3D 遊戲*

> **★ 設計要點**：學習 Shader 是進階美術與技術美術（Technical Artist）的核心技能。建議從 Shadertoy 等線上平台開始，寫簡單的程式 Shader；進階到 Unity 的 Shader Graph 或 Unreal 的材質編輯器後，會發現很多「看似魔法」的視覺效果其實是幾行 Shader 程式碼。

### 光線追蹤  `Ray Tracing`

模擬光線在 3D 空間中的真實物理行為的渲染技術。對螢幕上的每個像素，從虛擬攝影機射出光線，追蹤它與場景中物體的互動——反射、折射、吸收、散射等——以計算該像素的最終顏色。相較傳統光柵化，光線追蹤能提供真實的反射（例如角色在水面上的完整倒影）、精準的陰影（柔和的陰影邊緣、接觸陰影）、自然的全局光照（間接光照亮暗處）。

2018 年 NVIDIA RTX 20 系列顯示卡首次將硬體光線追蹤帶入消費市場，之後 PlayStation 5 與 Xbox Series X|S 也支援。光線追蹤極度消耗運算資源，因此通常搭配 DLSS、FSR 等 AI 升頻技術使用以維持可接受的幀率。

> **▶ 代表作品**：*電馭叛客 2077（RT Overdrive）、控制、心靈殺手 2、戰慄時空 2：RTX、印第安納瓊斯：古老之圈、黑神話：悟空*

> **★ 設計要點**：光線追蹤的導入需要考量目標平台與玩家硬體。建議提供「開關選項」並設計多個等級（低／中／高／極致），讓不同配置的玩家都能找到適合的設定。如果遊戲核心畫風是卡通或像素，光線追蹤未必帶來視覺加分，反而是不必要的成本。

### 路徑追蹤  `Path Tracing`

光線追蹤的完全體、電影級渲染的終極技術。相較於傳統光線追蹤只選擇性計算反射、陰影等特定光照效果（仍混合光柵化），路徑追蹤則是「從相機射出的每一道光線，都會在場景中多次反彈，完整模擬光子在現實中的所有行為」——直接光、間接光、漫反射、鏡面反射、焦散（Caustics，水杯映在桌面的光斑）、次表面散射（光穿過皮膚或蠟燭）全部統一由同一套物理公式計算。效果上最接近離線渲染的電影 CG 品質。

代價極高——在 4K 解析度開啟路徑追蹤，即便是 RTX 4090 這樣的旗艦顯卡也必須搭配 DLSS 性能模式才能維持 60FPS。《電馭叛客 2077》的 RT Overdrive 模式是第一個讓大眾認識路徑追蹤威力的作品，Night City 的霓虹光在濕滑路面上的自然暈染完全改變了遊戲的視覺基調。

> **▶ 代表作品**：*電馭叛客 2077（RT Overdrive）、心靈殺手 2、黑神話：悟空、印第安納瓊斯：古老之圈、Portal with RTX、Quake II RTX、毀滅戰士：黑暗時代、戰慄時空 2：RTX、F1 25、007：First Light、惡靈古堡：安魂曲*

> **★ 設計要點**：路徑追蹤目前是技術展示而非主流體驗——它需要 RTX 4070 以上 ＋ DLSS 才能在 1440p 正常運作。設計時應視其為「效能怪獸選項」：大多玩家不會開，但為硬體發燒友與技術媒體留下令人驚嘆的畫面是品牌價值。預計 2026-2028 年隨著 DLSS 5 與下一代主機問世，路徑追蹤將逐步走向主流。

### 全局光照 / Lumen  `Global Illumination (GI) / Lumen`

模擬光線在場景中多次反彈、照亮間接區域的技術。沒有 GI 的遊戲，陰影中的物體就是死黑一片；有了 GI，陽光照在紅牆上反彈到地板上，會讓地板染上一層淡淡的紅色調，這種光的「溫暖感」正是電影級畫面的秘密。傳統做法是「烘焙」（Baked GI，預先計算並存成貼圖，省效能但只能用於靜態場景）。Unreal Engine 5 的 Lumen 是革命性的即時動態 GI 系統——光線隨物體移動即時重算，讓動態世界有了真實的間接光。

> **▶ 代表作品**：*Unreal Engine 5 的 Lumen：堡壘之夜、黑神話：悟空、無間冥想；傳統 Baked GI：幾乎所有 2020 年前的遊戲*

> **★ 設計要點**：GI 對室內場景與有色光源（霓虹燈、火焰、水中反光）的質感提升最明顯。對純戶外陽光下的遊戲提升有限。考量性能時，即時 GI 是昂貴選項，小型團隊烘焙 GI 仍是合理的選擇。

### DLSS、FSR、XeSS  `DLSS / FSR / XeSS (AI Upscaling)`

AI 驅動的畫面升頻技術，可在較低的內部解析度渲染畫面後，透過 AI 模型放大到目標解析度，兼顧畫質與效能。NVIDIA 的 DLSS（Deep Learning Super Sampling）需要 RTX 系列顯卡的 Tensor Core；AMD 的 FSR（FidelityFX Super Resolution）採用開源方案、不限廠商；Intel 的 XeSS（Xe Super Sampling）是 Intel Arc 顯卡的方案但也提供跨廠商版本。

2026 年 CES 發表的 DLSS 4.5 進一步進化——AI 實際繪製螢幕上 24 個像素中的 23 個（僅 1/24 像素由傳統渲染產生），並引入「動態多幀生成」（Dynamic Multi Frame Generation），在 RTX 50 系列上最多可產生 6 倍的幀率。DLSS 4.5 使用第二代 Transformer 模型提升了畫面穩定性、消除殘影、抗鋸齒表現。

> **▶ 代表作品**：*幾乎所有 2020 年後的 AAA 遊戲都支援其中一種或多種*

> **★ 設計要點**：AI 升頻已是現代 GPU 渲染管線的必要部分，非選配。開發時應同時支援多種方案以涵蓋所有硬體。關鍵是「原生解析度」與「升頻後」的視覺差異要經過美術確認——AI 有時會把畫面的細節（如草葉、髮絲、遠景文字）處理得過於平滑或產生鬼影。

### DLSS 5／神經渲染  `DLSS 5 / Real-time Neural Rendering`

NVIDIA 於 2026 年 3 月 16 日 GTC 2026 發表、預計 2026 年秋季上市的新一代 DLSS。這是自 2018 年即時光線追蹤問世以來電腦圖學的最大突破。Jensen Huang 稱其為「圖形領域的 GPT 時刻」。

與前幾代 DLSS 專注於「提升效能」不同，DLSS 5 的核心是「提升視覺保真度」。它建立在 DLSS 4.5 的升頻與多幀生成之上，再用一個神經網路模型接管「光照與材質」——輸入遊戲當前幀的顏色與運動向量，由 AI 為場景注入照片級的光照、皮膚次表面散射、布料質感、玻璃反射等效果，且完全錨定於開發者的美術風格與 3D 世界內容。簡言之，過去用數學規則「近似」光線物理，現在訓練 AI「理解」光線物理。

目前確認支援 RTX 50 系列。首發合作的廠商包括 Bethesda（Starfield）、CAPCOM、Ubisoft、Warner Bros. Games、網易、騰訊、NCSOFT 等業界巨頭。發表會示範將 Starfield、Resident Evil Requiem、EA Sports FC、霍格華茲的傳承等遊戲畫面提升至「好萊塢視覺特效」等級。

> **▶ 代表作品**：*首發合作遊戲包括 Starfield、Resident Evil Requiem、EA Sports FC、霍格華茲的傳承等；完整清單將在 2026 年秋季上市時公布*

> **★ 設計要點**：DLSS 5 改變了「頂尖畫質」的定義——它不只是渲染得更準，而是讓 AI 理解場景本身。對開發者而言，意味著不需要再手刻材質的每個物理參數，就能達成電影級光影。但也帶來爭議：部分社群質疑「AI 介入會破壞美術方向」。建議：將 DLSS 5 視為「可選的畫質增益」而非「強制渲染管線」，保留原生渲染作為美術風格的保底。

### 幀率  `Frame Rate (FPS)`

每秒顯示的畫面數，單位是 FPS（Frames Per Second）。常見標準：30FPS（電影感、省效能、舊主機常見）、60FPS（流暢、主流標準）、120FPS（競技級、現世代主機可選）、144FPS 以上（PC 高刷新率電競螢幕）。穩定性比絕對數值更重要——穩定的 30FPS 體感優於忽高忽低的 45FPS。現代主機提供「畫質模式」（Fidelity Mode，30FPS 換畫質）與「效能模式」（Performance Mode，60FPS 換畫質）讓玩家自選。

> **▶ 代表作品**：*所有即時遊戲*

> **★ 設計要點**：目標幀率應根據遊戲類型決定：競技射擊至少 60FPS，動作格鬥建議 60FPS（硬直幀數是以 60FPS 為標準設計），回合制策略 30FPS 即可。切勿在設計階段追求「極致畫質」卻無法達到目標幀率——玩家能忍受略醜但不能忍受卡頓。

### HDR  `High Dynamic Range`

「高動態範圍」，讓畫面的明暗對比拉得更大——亮的地方更亮（如正午太陽、雷射、霓虹燈）、暗的地方更暗但仍有細節。HDR 需要螢幕硬體支援（顯示器標有「HDR10」「Dolby Vision」等），配合遊戲內 HDR 模式才能生效。HDR 對夜景、夕陽、光影對比強烈的場景提升最明顯。

> **▶ 代表作品**：*心靈殺手 2、最後生還者 二部曲、赤紅血緣 2、絕大多數 PS5/Xbox Series 獨佔作品*

> **★ 設計要點**：HDR 的校正極為重要——錯誤的 HDR 設定會讓畫面偏暗或過曝。好的遊戲會提供引導式的 HDR 校正畫面（通常顯示不同亮度的太陽讓玩家調整）。建議開發時購買 HDR 參考螢幕進行實際測試。

### 細節層級  `LOD (Level of Detail)`

根據物件距離攝影機的遠近，動態切換不同精細度模型的技術。近距離使用高多邊形模型（LOD0，完整細節），中距離使用中等模型（LOD1、LOD2，簡化細節），遠距離使用低模型（LOD3 以上，甚至是一張公告板貼圖）。這對大場景的效能至關重要——假如一個城市地圖內所有建築物都用 LOD0 渲染，連 RTX 5090 都會跪。Unreal Engine 5 的 Nanite 技術則革命性地讓 LOD 自動化——開發者丟進電影級高模，引擎自動在即時運算中決定每個像素需要多少三角形。

> **▶ 代表作品**：*所有包含大型場景的 3D 遊戲、Unreal Engine 5 專案普遍使用 Nanite*

> **★ 設計要點**：LOD 的切換距離設計得不好會有「Pop-in」現象（物件在玩家眼前突然變清晰或變模糊）。LOD 模型的製作也要確保輪廓相似，避免距離變化時物體形狀跳變。

### 布娃娃物理  `Ragdoll Physics`

角色死亡或失去平衡後，身體關節不再由動畫驅動、改由物理引擎接管的技術。名字源自布娃娃（Ragdoll）被拋擲時的隨意姿態——每個關節都有合理的物理連接但沒有主動運動。Ragdoll 讓敵人死亡時的姿勢每次都不同（被打到頭、被打到腳的倒下姿勢不同），極大地增加了戰鬥的視覺豐富度。

> **▶ 代表作品**：*GTA 系列（早期的經典範例）、戰地系列、絕地戰兵 2*

> **★ 設計要點**：Ragdoll 的參數調整是工作量極大的隱藏工作——關節的硬度、摩擦力、質量分布都會影響「倒下看起來自不自然」。過硬的關節讓角色像木偶，過軟則像果凍。

### 動作捕捉  `Motion Capture (MoCap)`

用感測器或攝影機記錄真人演員的動作、表情、聲音，轉換為遊戲角色動畫的技術。現代 MoCap 分全身動作（Body Mocap，穿感測器服或標記點服進入攝影棚）與表情捕捉（Facial Mocap，戴頭盔攝影機對準臉部記錄肌肉細節）。電影級 MoCap 如《秘境探險 4》、《最後生還者二部曲》的表演已經與真人電影沒有區別。近年也有 AI 輔助的「單一攝影機動作捕捉」技術，讓獨立團隊也能用手機錄影提取動作數據。

> **▶ 代表作品**：*秘境探險系列、最後生還者系列、死亡擱淺、碧血狂殺 2*

> **★ 設計要點**：MoCap 的成本極高（攝影棚、演員、後期清理），但能產生手 K 動畫無法達到的自然感。3A 與獨立遊戲的差距在此最明顯。替代方案：購買現成的動作資料庫（如 Mixamo）、使用 AI 生成動作（但目前品質仍有限）。

### VR／AR／MR／XR  `VR / AR / MR / XR`

沉浸式媒體的四個術語。VR（Virtual Reality，虛擬實境）用頭戴裝置將玩家完全帶入虛擬世界（Meta Quest、PSVR2、Valve Index）；AR（Augmented Reality，擴增實境）在現實世界上疊加虛擬資訊（Pokémon GO、Apple Vision Pro 部分功能）；MR（Mixed Reality，混合實境）是 AR 的進階版，虛擬物件會與真實環境互動（Microsoft HoloLens）；XR（Extended Reality）是以上全部的統稱。戰慄時空：艾莉克斯證明了 VR 可以做出 3A 等級的完整體驗。

> **▶ 代表作品**：*戰慄時空：艾莉克斯、Beat Saber、生化奇兵 VR、Pokémon GO、Demeo*

> **★ 設計要點**：VR 開發的特殊挑戰：暈 3D（Motion Sickness）、手部操作設計、UI 不能「貼」在畫面上（必須在 3D 空間中）、效能要求極高（必須穩定 90FPS 以上否則玩家會暈）。建議不要把 2D 遊戲「移植」到 VR——必須從頭設計適合 VR 的互動。

### 觸覺回饋／自適應扳機  `Haptic Feedback / Adaptive Triggers`

PlayStation 5 DualSense 手把引入的兩項革命性技術。觸覺回饋（Haptic Feedback）取代傳統震動馬達，使用高精度的線性執行器，能模擬細膩的觸感——雨滴打在金屬上的清脆感、在沙地行走的沉重、弓弦拉緊的緊繃感。自適應扳機（Adaptive Triggers）則是 L2／R2 扳機內部有可變阻力機構，能模擬武器的不同操作手感——拉弓時扳機會隨拉力逐漸變硬、扳機鎖死在卡彈狀態、扳機有兩段式射擊點等。兩項結合讓遊戲體驗擁有前所未有的物理感。

> **▶ 代表作品**：*星空戰士、惡靈古堡 4 重製版、漫威蜘蛛人 2、戰神：諸神黃昏*

> **★ 設計要點**：這些功能目前僅 PS5 支援（PC 版用 DualSense 連線部分支援），但為遊戲加分極大。開發多平台版本時要考慮將 DualSense 的獨特體驗視為「PS5 版的加分項」而非「所有平台都要有」的基本功能。

# 第七章：敘事設計

遊戲敘事不同於電影或小說——它必須考慮玩家的主動參與。好的遊戲敘事讓玩家感到自己是故事的一部分，而非旁觀者。

### 英雄之旅  `The Hero's Journey`

神話學家約瑟夫．坎伯（Joseph Campbell）歸納的敘事結構，是西方故事敘述的主幹模型。核心步驟包括：平凡世界（主角的日常）→冒險召喚→拒絕召喚→遇見導師→越過第一道門檻→試煉與盟友→最大考驗→獲得報酬→歸返之路→再生→帶著寶物歸來。《星際大戰》《駭客任務》《哈比人》都是典型應用。許多 JRPG（勇者鬥惡龍、最終幻想）也採用此結構。

> **▶ 代表作品**：*最終幻想系列、勇者鬥惡龍系列、大神*

> **★ 設計要點**：英雄之旅不是公式，是骨架——填入不同血肉就是不同故事。學生練習時建議先用此結構寫 2,000 字的微型故事，感受每個階段的情緒轉折。

### 三幕劇結構  `Three-Act Structure`

源自古希臘戲劇、好萊塢編劇的標準敘事架構。第一幕「建立」（25%）：介紹主角、世界、現況；以「煽動事件」（Inciting Incident）推動進入第二幕。第二幕「對抗」（50%）：主角面對逐漸升級的挑戰，通常包含「中點逆轉」讓情勢急轉直下；以「最低點」（All is Lost）結束第二幕。第三幕「解決」（25%）：主角振作反擊，最終對決，收尾。

> **▶ 代表作品**：*絕大多數西方單人線性遊戲*

> **★ 設計要點**：三幕劇的節奏比例比內容本身更重要。玩家對「第一幕太長（無聊）」「第二幕無高潮（疲勞）」「第三幕草率（失望）」的感受都來自比例失衡。企劃初期就要規劃每一幕的遊玩時長分配。

### 起承轉結  `Kishōtenketsu`

東亞傳統敘事結構，不依賴衝突推動劇情。四個階段：起（Ki，介紹場景與角色）→承（Shō，發展情節）→轉（Ten，出現出人意料的新元素，通常與前文表面無關）→結（Ketsu，新元素與原有情節的關係被揭示並達成平衡）。宮本茂公開表示《薩爾達傳說》《超級瑪利歐》的關卡設計採用此結構——一關先介紹新機制（起）、讓玩家熟練（承）、引入變化或挑戰（轉）、綜合運用完成挑戰（結）。

> **▶ 代表作品**：*超級瑪利歐系列、薩爾達傳說系列、Journey*

> **★ 設計要點**：起承轉結是非衝突導向敘事的利器——特別適合探索類、療癒類、親子向的遊戲。也可以作為「單關設計」的結構而非整部遊戲的結構。

### 多重結局／真結局  `Multiple Endings / True Ending`

遊戲根據玩家選擇、成就、隱藏條件產生不同結局。常見分級：Bad Ending（壞結局，玩家犯錯或選擇黑暗路線）、Normal Ending（普通結局，完成主線）、Good Ending（好結局，做了額外努力）、True Ending（真結局，滿足特殊條件才能看到，通常揭示世界的終極真相）。《尼爾》系列、《歧路旅人》等作品的「真結局」往往需要 NG+ 或特定路線才能解鎖。

> **▶ 代表作品**：*尼爾：自動人形（A 到 E 五個結局）、Undertale（和平、中立、屠殺三條路線）、女神異聞錄系列*

> **★ 設計要點**：多重結局的設計陷阱：如果所有結局都一樣精彩，玩家會因為「都差不多」而失去探索動機；如果差異太大（壞結局草率），玩家會覺得被懲罰。解法：讓每個結局都有獨特的情感價值，而非單純的「好／壞」標籤。

### 分支敘事  `Branching Narrative`

允許玩家選擇影響劇情走向的非線性敘事結構。從簡單的「好／壞」結局分支，到複雜的多變數系統（每個選擇都會影響後續 N 個場景）。《巫師 3》、《柏德之門 3》、《極樂迪斯可》都是分支敘事的典範，其中《柏德之門 3》因為玩家可以用幾乎任何方式解決問題而被稱為「真正的互動敘事」。

> **▶ 代表作品**：*巫師 3、柏德之門 3、極樂迪斯可、底特律：變人*

> **★ 設計要點**：分支敘事的開發成本極高——每一條分支都需要完整的劇本、配音、場景。Quantic Dream 的做法是設計「流程圖」讓所有分支都能在主幹上重新匯合，以控制成本。小團隊建議採用「局部分支」——大多場景共享，關鍵節點分支。

### 對話樹  `Dialogue Tree`

分支對話系統的經典表現形式。NPC 說話後提供數個回應選項，玩家選擇後進入不同的對話分支，最終可能得到不同的資訊、任務、人際關係。高級的對話樹不只是「線性樹」，而是會根據玩家角色屬性（智力、說服、威嚇、種族、職業）開啟隱藏選項——《極樂迪斯可》的 24 種技能都會在對話中插入獨特的反應。

> **▶ 代表作品**：*質量效應系列、柏德之門 3、極樂迪斯可、異塵餘生系列*

> **★ 設計要點**：對話樹的設計挑戰是「讓選項都有意義」——避免「同義不同話」的假選項（兩個選項文字不同但結果一樣）。《質量效應》的對話輪盤（Dialogue Wheel）是一種折衷，把選項分為「善／中／惡」三類但仍有意義。

### 伏筆／麥高芬  `Foreshadowing / MacGuffin`

兩個常用的敘事技巧。伏筆（Foreshadowing）是在故事早期埋下暗示，在後期揭示其意義，讓玩家產生「原來如此！」的恍然大悟。麥高芬（MacGuffin，由希區考克命名）則是推動劇情發展的「目標物件」——所有角色都為它奮鬥，但它本身是什麼並不重要，重要的是它引發的角色互動。《印第安納瓊斯》的聖杯、《駭客任務》的母體都是麥高芬；《質量效應》的秘密通道則充滿伏筆。

> **▶ 代表作品**：*《尼爾：自動人形》的所有結局都建立在前文的大量伏筆之上；《荒野大鏢客 2》的結核病暗示是經典伏筆*

> **★ 設計要點**：伏筆的技巧在於「輕」——不能太明顯（變成劇透）也不能太隱晦（玩家事後察覺不到）。建議讓至少 30% 的玩家在重玩或重看時能發現「原來這裡已經暗示了」。

### 遊戲敘事失調  `Ludonarrative Dissonance`

由遊戲設計師 Clint Hocking（《刺客任務：契約》《極地戰嚎 2》設計師）於 2007 年提出的概念，指「遊戲玩法」（Ludo）與「敘事內容」（Narrative）之間的不協調。經典案例：劇情中主角是慈愛的父親，但玩法上我們讓他殺了一千多個敵人；劇情強調「資源稀缺」，但玩法上商店裡的補給品堆積如山。

> **▶ 代表作品**：*秘境探險系列（Nathan Drake 劇情溫和但殺人無數）、最後生還者系列*

> **★ 設計要點**：遊戲敘事失調是所有動作冒險遊戲的共通挑戰，很難完全避免。解決方向：讓戰鬥有代價（主角每次殺人後表情沉重）、在劇情中直接承認這個問題（《最後生還者 二部曲》直接探討暴力的後果）、或是用抽象化處理（被打敗的敵人化為煙霧，如《超級瑪利歐》）。

### 玩家代理感  `Player Agency`

玩家感覺自己的選擇真正影響了遊戲世界的程度。高代理感的遊戲讓玩家覺得「這個故事是因為我而發生的」，低代理感的遊戲則讓玩家覺得「我只是在看別人演戲」。注意：代理感不等於選擇數量——《柏德之門 3》有驚人的選擇數，但其代理感來自於「每個選擇都真的影響世界」。有些遊戲有大量選擇但結果相同，反而會讓玩家感到被愚弄。

> **▶ 代表作品**：*柏德之門 3、異塵餘生：新維加斯、極樂迪斯可*

> **★ 設計要點**：打造代理感的最有效方法不是「提供更多選擇」，而是「讓每個選擇都有後果」。後果可以是劇情分支、也可以是 NPC 態度變化、甚至只是對話中被提起（「我記得你當時救了我」）。

### 難度曲線  `Difficulty Curve`

遊戲難度隨進度變化的設計。理想的難度曲線不是單調上升，而是有起伏——在高難度段落後安排輕鬆段落讓玩家喘息，或在介紹新機制後有練習期再挑戰。「挑戰遞進」（Escalating Challenge）的原則是：每個新敵人或新機制先讓玩家遭遇一次（驚嚇）、然後給時間練習、最後在 Boss 戰綜合考驗。

> **▶ 代表作品**：*超級瑪利歐系列的關卡設計是教科書級的難度曲線*

> **★ 設計要點**：建議在每個大關結尾安排「技能檢測點」——如果玩家在此受挫，代表前面的教學沒有到位，應該回頭檢討而非單純加入指引文字。

# 第八章：產業與開發實務

了解遊戲產業的運作邏輯對於企劃、行銷、職涯規劃都至關重要。本章涵蓋開發流程、商業模式、發行實務等面向。

### GDD 遊戲設計文件  `GDD (Game Design Document)`

描述遊戲設計各層面的正式文件，是企劃團隊的工作藍圖。典型 GDD 包含：遊戲概念（30 秒內能說清的 Elevator Pitch）、目標玩家、核心玩法、系統設計、關卡設計、劇情大綱、美術風格、音效方向、技術需求、開發時程、預算規劃等。現代 GDD 已從「一份巨大的 Word 檔」演化為「活文件」——用 Confluence、Notion 等協作工具建立可持續更新的線上文件庫。

> **▶ 代表作品**：*是任何正式遊戲開發的必備工具*

> **★ 設計要點**：學生常犯的錯誤是把 GDD 寫成小說——花大量篇幅描述劇情但缺乏機制細節。實務上 GDD 的目的是讓工程師能開始寫程式、美術能開始製作資產、音樂家能開始作曲。每一段文字都要回答「這段怎麼實作？需要多少時間？」

### Alpha／Beta 版本  `Alpha / Beta Build`

遊戲開發進度的里程碑。Alpha 版本代表「所有主要功能都已實作，內容完整可玩，但有大量 Bug 和不平衡」——內部測試階段。Beta 版本代表「功能完整、內容鎖定、只做 Bug 修復與平衡調整」——外部測試階段，可能包含封閉測試（Closed Beta，少數玩家）、公開測試（Open Beta，所有人可參加）。Gold Master（GM）則是最終出片版本。

> **▶ 代表作品**：*所有商業遊戲開發流程*

> **★ 設計要點**：小團隊常混淆 Alpha 與 Beta——功能還沒做完就開公測是常見的錯誤（因為回饋的 Bug 大多是已知問題，浪費了寶貴的測試機會）。嚴格分辨階段：「能不能動」是 Alpha，「爽不爽玩」是 Beta。

### 3A／AAA 遊戲  `AAA Game`

業界術語，指擁有極高預算、大型開發團隊、全球行銷投入的大型遊戲。預算通常從數千萬到數億美元，開發團隊數百至上千人，開發週期 3 至 7 年。3A 遊戲追求技術與製作品質的頂峰，但也承擔巨大財務風險——近年多款 3A 遊戲的失敗（Concord、Anthem、Redfall）讓業界開始重新思考這個模式。

> **▶ 代表作品**：*俠盜獵車手系列、最後生還者、戰地系列、上古卷軸系列、Red Dead Redemption*

> **★ 設計要點**：「AA」（雙 A）與「3A」（三 A）的分界模糊。近年來 AA 反而有復興趨勢——成本較低（數百萬至千萬美元）、團隊中型、敢於嘗試獨特玩法，如 Hi-Fi Rush、A Plague Tale 系列。對小團隊來說，AA 比 3A 更有存活空間。

### 獨立遊戲  `Indie Game`

由獨立開發者或小型團隊製作、不依賴大型發行商資金的遊戲。獨立遊戲的優勢在於創意自由、決策靈活、能承擔實驗性風險。劣勢則是預算有限、行銷能力有限、技術資源不足。Steam、Itch.io、Epic Games Store 等數位平台大幅降低了獨立遊戲的發行門檻。

> **▶ 代表作品**：*空洞騎士、Undertale、星露谷物語、Celeste、巴拉特羅*

> **★ 設計要點**：「獨立」不再是規模標籤而是精神標籤——《空洞騎士》最初是兩個人做的，但品質與影響力超越許多 3A。對學生作品來說，「獨立遊戲」是最可行的目標——鎖定一個清晰的核心玩法，做到極致。

### 搶先體驗  `Early Access`

遊戲尚未正式完成前就開始販售並允許玩家遊玩的模式。玩家的反饋會持續影響遊戲的開發方向。這種模式讓開發者能提前獲得收入來支持開發，但也有風險——有些遊戲永遠停留在 Early Access 狀態（即俗稱的 Early Access 地獄）。成功案例如《死亡細胞》從 Early Access 變成完整作品，失敗案例則是無數從此消失的遊戲。

> **▶ 代表作品**：*巴拉特羅、英靈神殿、殺戮尖塔、幻獸帕魯*

> **★ 設計要點**：進入 Early Access 需要清晰的承諾：什麼時候推出 1.0、會新增哪些內容、什麼時候定價會調整。Steam 對 Early Access 有明確規範，違規會被下架。

### DLC／季票／擴充包  `DLC / Season Pass / Expansion`

遊戲上市後的付費追加內容。DLC（Downloadable Content）是泛稱，涵蓋從服飾造型（Cosmetic DLC）到完整新劇情（Story DLC）。擴充包（Expansion）是內容份量最大的 DLC，可視為「半款新遊戲」——加入新地圖、新職業、新劇情（如《血源詛咒：古獵人》《巫師 3：石之心／血與酒》）。季票（Season Pass）則是預購多個未來 DLC 的組合優惠。

> **▶ 代表作品**：*巫師 3 擴充包（業界公認 DLC 典範）、艾爾登法環：黃金樹幽影、柏德之門 3（未來 DLC）*

> **★ 設計要點**：DLC 的設計原則：基礎遊戲本身必須是完整體驗，DLC 是「上方的糖霜」而非「缺失的拼圖」。如果玩家買本體後感覺「內容不完整，被逼著再買 DLC」，會嚴重傷害品牌。

### 首日更新  `Day One Patch`

遊戲正式發售當天推送的更新檔。來源是：實體光碟印製需要在發售前數月完成，但開發直到最後幾週都在修 Bug 與調整平衡——這些修改會包在 Day One Patch 中。現代玩家已視 Day One Patch 為標配。但若 Patch 過大（例如數十 GB），則暗示遊戲未完成就出貨。

> **▶ 代表作品**：*幾乎所有現代遊戲*

> **★ 設計要點**：Day One Patch 不應包含「開場後才能玩」的內容——部分玩家（如偏遠地區網路慢）會在完整 Patch 下載完成前開始遊玩。核心內容必須在光碟／基礎安裝包中。

### 發行商與開發商  `Publisher vs Developer`

兩個經常被混淆的角色。開發商（Developer）是做遊戲的團隊；發行商（Publisher）是出錢、行銷、發行的公司。同一遊戲的開發商和發行商可能不同——例如《黑暗靈魂》的開發商是 FromSoftware，發行商早期是 Bandai Namco。部分公司兩者皆做（如任天堂、CAPCOM、Ubisoft）。發行商提供資金與行銷但通常也掌握 IP 所有權——這是 FromSoftware 現在改由 Kadokawa 集團主導《艾爾登法環》發行的背景因素之一。

> **▶ 代表作品**：*發行商：EA、Activision、任天堂、PlayStation Studios；開發商：Blizzard、Obsidian、Arkane*

> **★ 設計要點**：學生與獨立開發者需要理解：找發行商不是「幫你賣」而是「與你分拆利潤」。典型分潤可能是發行商 50% 至 70%。完全獨立發行（Self-Publish）需要自備行銷與客服能力。

### 垂直切片  `Vertical Slice`

展示遊戲最終品質的完整體驗片段，涵蓋所有主要系統但範圍較小。可用於內部評估、向投資者展示、或向媒體展示。一個典型的垂直切片可能是 15 至 30 分鐘的完整遊玩體驗，但其中的每一個元素（美術、音效、關卡設計、機制）都達到最終遊戲的品質標準。

> **▶ 代表作品**：*遊戲開發實務工具*

> **★ 設計要點**：垂直切片是申請資金（政府補助、創投）與媒體展示的利器。製作垂直切片的成本比原型高但比完整遊戲低，是中間平衡點。對學生專題作品來說，「一個完整的垂直切片」比「一個不完整的大作」更有說服力。

### 在地化  `Localization (L10N)`

將遊戲翻譯並適應當地文化的過程。不只是文字翻譯（UI、對話、劇情、網站），還包括語音配音、文化調整（符號、顏色、手勢在不同文化的含義不同）、法律合規（分級制度）、支付方式在地化。優秀的在地化能讓遊戲在新市場獲得成功，糟糕的在地化則會毀掉一款好遊戲。「L10N」是 Localization 的縮寫（L 到 N 中間 10 個字母）。

> **▶ 代表作品**：*原神（多國語音）、Final Fantasy XIV（極高品質的多語化）、霸王的大陸（中文漢化延續數年）*

> **★ 設計要點**：台灣遊戲企劃常忽略繁體與簡體的差異不只是字形——用詞、語氣、梗都不同。《原神》台灣版本選擇了「Moondial／月亮」這類在地用語而非中國用法，獲得好評。

### 年齡分級  `Age Rating`

各國官方或行業組織對遊戲內容的分級標示。北美：ESRB（Everyone、E10+、Teen、Mature、Adults Only）；歐洲：PEGI（3、7、12、16、18）；日本：CERO（A 到 Z）；台灣：採類似 ESRB 的 CSR 分級（普遍、保護、輔導 12 歲、輔導 15 歲、限制）。分級會影響遊戲能在哪些平台、哪些店面販售——AO 或 CERO Z 級在多數實體店面會被拒絕上架。

> **▶ 代表作品**：*所有正式發行的商業遊戲*

> **★ 設計要點**：分級不只是被動申請——開發時就應該決定目標分級（例如「我們要做 PEGI 16」），並據此調整內容。為了追求「限制級才酷」而加入不必要的暴力或色情內容，會失去大量潛在玩家。

### 群眾募資  `Crowdfunding`

透過 Kickstarter、Indiegogo 等平台向一般大眾募集遊戲開發資金的模式。成功案例如《尚氣英雄》《Hollow Knight Silksong》（原作 Kickstarter 募資）、《Bloodstained: Ritual of the Night》。失敗案例亦不勝枚舉——募資達成但遊戲難產或無法交付。近年中國與日本的玩家對 Kickstarter 的熱情已下降，成功案例更集中在歐美獨立開發者。

> **▶ 代表作品**：*Kickstarter 上：Undertale、Shovel Knight、Hollow Knight；日本：Yakuza Kaiwai、異塵餘生翻譯計畫*

> **★ 設計要點**：群眾募資的本質是「預售 + 行銷」——你實際上是在遊戲尚未完成前就銷售它。建議有完整的 demo 與明確的時程規劃，否則延遲交付會嚴重傷害你的聲譽。

### Crunch 時期  `Crunch`

遊戲開發後期為了趕上發行日期而進行的長時間加班。原意是「用力壓榨」。Crunch 期間員工每週工作 60 至 100 小時、週末無休、甚至數月不能正常休息是常態。近年來產業開始反思 Crunch 文化，但在 Rockstar、Naughty Dog、CD Projekt Red 等公司仍然存在。2020 年《電馭叛客 2077》發售前的 Crunch 引發全球媒體關注。

> **▶ 代表作品**：*業界長期存在的慣例問題*

> **★ 設計要點**：健康的遊戲開發應該避免 Crunch——它不僅不人道，實際上也會降低生產力（疲勞員工寫的 Bug 更多）。良好的專案管理、合理的範圍控制、願意延期（而非強迫員工犧牲）是根本解方。作為企劃／主管，應主動觀察團隊狀態並推動延期決策。

# 第九章：手機遊戲特有機制

手機遊戲已是全球遊戲市場最大的區塊。其獨特的商業模式與玩家行為造就了許多特殊機制。

### 體力系統  `Stamina / Energy System`

限制玩家每日遊玩時間的資源系統。玩家執行特定動作（如進入戰鬥副本）會消耗體力，體力用完就無法繼續。體力隨時間自動恢復（例如每 6 分鐘恢復 1 點），或可以用付費道具（月卡、寶石）加速恢復。這種設計源自 Facebook 遊戲時代，確保玩家每天都會定時上線檢查體力。現代手遊多採「寬鬆體力＋重度活動」的混合模式——平時體力花不完，大型活動時才會感到緊張。

> **▶ 代表作品**：*原神（樹脂）、Fate/Grand Order（AP）、絕大多數日韓手遊*

> **★ 設計要點**：體力設計要平衡「限制」與「自由」。過嚴（玩不了幾分鐘就沒體力）會讓玩家流失，過寬（體力永遠用不完）會失去系統意義。研究你的目標玩家每日遊玩時長，據此設計體力恢復速度。

### 每日每週任務  `Daily / Weekly Quest`

每天或每週重置的任務系統，提供固定獎勵。目的是建立玩家的日常遊玩習慣——「既然已經打開遊戲了，不如順便做個日常」。典型任務包括「擊敗 10 個敵人」「消耗 N 點體力」「登入即可」等，大多設計為 5 至 15 分鐘可完成。

> **▶ 代表作品**：*所有 GaaS 手遊*

> **★ 設計要點**：日常任務的陷阱：如果設計過於繁瑣或耗時，會讓玩家感到「被迫上班」而非「享受遊戲」。建議提供「任務委託」「掃蕩」等功能，讓老玩家能快速完成。

### 首抽 / Reroll  `Reroll`

玩家在遊戲一開始反覆進行初始抽卡、直到抽到心儀的角色才正式開始遊戲的行為。「Reroll」即「重新擲骰」。對手遊來說這是複雜的現象——一方面遊戲公司不希望玩家 Reroll（浪費伺服器資源、破壞經濟平衡），另一方面 Reroll 社群的活躍也是遊戲熱度的展現。

> **▶ 代表作品**：*原神、蒼藍檔案、鳴潮、絕區零*

> **★ 設計要點**：Reroll 的便利性本身就是設計選擇：可以透過「帳號綁定在第 N 章自動鎖定」「教學完就綁 Google／Apple 帳號」等機制增加 Reroll 門檻，或反過來簡化 Reroll（提供遊客帳號、初始 10 連免費）來歡迎新玩家嘗試。

### 課金／抽卡  `Gacha / Microtransaction`

玩家用真實金錢購買虛擬貨幣、再用虛擬貨幣購買遊戲內物品或進行抽卡的機制。商業模式核心：80/20 法則的極端版——手遊營收中 80% 以上來自 5% 以下的重度消費玩家（稱為「鯨魚」Whale，或極端的「巨鯨」Mega-whale）。「課金」是台灣用語，源自日文「課金」（かきん，指計費）；中國用「氪金」（取「氪」與「課」音近的諧音梗）；兩者意思相同。

> **▶ 代表作品**：*所有 F2P 手遊*

> **★ 設計要點**：倫理議題：有研究指出轉蛋的心理學機制與賭博相似，特別是對青少年與經濟脆弱群體的影響。部分國家（比利時、荷蘭）已將某些形式的轉蛋認定為賭博並加以限制。作為開發者，需要考慮自己的設計對玩家福祉的長期影響。

### 聯動活動  `Collaboration (Collab)`

兩個 IP 跨界合作的限時活動。典型如原神與《Honkai: Star Rail》的角色互訪、Final Fantasy XIV 與《Final Fantasy XVI》聯動、手遊與動漫作品聯動（如《Fate/Grand Order》與各種動畫）。聯動是吸引新玩家、喚回老玩家、帶動話題的重磅武器，但成本極高（版權費 + 雙方協調）。

> **▶ 代表作品**：*Fate/Grand Order 經典聯動系列、《原神》與《Fate/stay night》傳聞、Fortnite 與漫威、星戰等*

> **★ 設計要點**：聯動的設計目標不只是「賣角色」——要讓兩邊 IP 的粉絲都滿足。最佳聯動會在劇情上打造「兩世界交會」的橋段，而非單純把客串角色丟進遊戲。

### Tier List  `Tier List`

玩家社群對角色強度的排名系統，通常分 S（Super Tier，最強）到 D 或 F（最弱）階。Tier List 是手遊、格鬥、MOBA 等所有有角色／英雄選擇的遊戲的標準產物。它影響新玩家的抽卡決策（「這個 S Tier 值得課金」）、競技玩家的角色選擇（「Meta 就是選這幾隻」）、以及平衡性討論（「這個角色太強，下次更新該 Nerf 了」）。

> **▶ 代表作品**：*所有競技與手遊社群*

> **★ 設計要點**：官方通常不發布 Tier List（避免玩家對被評為低階的角色不滿），但會密切關注社群 Tier List 作為平衡參考。作為開發者，健康的 Tier List 分布應該是「每個 Tier 都有數個角色」，而非「只有 2 個 S Tier 輾壓全部」。

### 掃蕩  `Sweep / Auto Clear`

手遊中讓玩家用體力或特定道具直接獲得副本獎勵、跳過實際戰鬥動畫的功能。通常在通關副本若干次或取得三星評價後解鎖。掃蕩是對「重複刷取」的重要 UX 改善——如果玩家已經打過同一個副本 100 次，再讓他每次都看完 5 分鐘戰鬥動畫是酷刑。

> **▶ 代表作品**：*大多數手遊（特別是 JRPG 手遊）、明日方舟、公主連結*

> **★ 設計要點**：掃蕩是玩家留存的關鍵功能——沒有掃蕩的現代手遊會被評價為「肝」「老派」。但掃蕩的門檻設計也有學問：太早開放（首通就能掃蕩）會讓戰鬥動畫被跳過，失去內容曝光；太晚則折磨玩家。

### 限時活動  `Limited-Time Event`

在特定時間段內才能參加、結束後獎勵消失的活動。製造 FOMO 心理，促使玩家定期上線。典型週期：大型改版（每 6 至 8 週）、節日活動（聖誕、春節、萬聖節）、週年慶。Fear of Missing Out（FOMO，怕錯過症）是這類設計的心理基礎——玩家不是因為想玩而上線，而是因為不想錯過而上線。

> **▶ 代表作品**：*所有 GaaS 遊戲*

> **★ 設計要點**：過度依賴 FOMO 會讓玩家疲勞進而退坑。健康的作法：限時活動的「核心獎勵」可以常駐或之後復刻，真正稀缺的是「活動限定裝扮」這類不影響戰鬥力的東西。

### 自動戰鬥  `Auto Battle`

讓 AI 代替玩家控制角色進行戰鬥的功能。這是手遊的爭議功能——支持者認為它解放了玩家的手指（特別是在通勤時），反對者認為它「讓遊戲自己玩自己」失去了遊戲的意義。現代手遊多採折衷：日常副本可以掛機，關鍵 Boss 與 PvP 則強制手動。

> **▶ 代表作品**：*原神（有限度）、公主連結、明日方舟*

> **★ 設計要點**：自動戰鬥的設計挑戰：AI 的策略永遠不如頂尖玩家，但如果 AI 表現太差會讓玩家覺得「浪費體力」。建議讓 AI 執行 80% 的決策正確率即可——更聰明的 AI 反而會壓縮手動遊玩的價值感。

### 公會戰  `Guild War / Alliance War`

手遊中公會（玩家組成的社交組織）之間的競賽模式。形式多樣：跨公會 Boss（多個公會同時挑戰 Boss，傷害排名獲獎勵）、公會對戰（一對一互相挑戰）、領地爭奪（佔領地圖格子）等。公會戰的核心價值不是獎勵本身，而是創造「我的隊友需要我」的社交壓力——退坑意味著讓公會失望。

> **▶ 代表作品**：*夢幻模擬戰、永恆戰士、七大罪：光與闇之交戰*

> **★ 設計要點**：公會戰是手遊留存率的大殺器，但設計時要避免「強迫全員上線」的壓力（特別是有時區差的國際公會）。可提供「不參加也沒損失，參加有獎勵」的柔性激勵。

# 第十章：電子競技

電子競技（Esports）已發展為全球性的產業，擁有專業聯賽、職業選手、贊助商與媒體報導。理解電競術語對於設計面向競技的遊戲至關重要。

### 排名等級系統  `ELO / MMR / Ranked Tier`

ELO 是源自西洋棋的評分系統，勝者從敗者處獲得分數，分數差越大則每場能獲得的分數變化越小。MMR（Matchmaking Rating）是遊戲內部的隱藏分數，用於配對；Ranked Tier（顯示段位）則是將 MMR 映射到「青銅／白銀／黃金／白金／鑽石／大師／菁英／王者」等視覺化階層。段位與 MMR 有時不一致——新玩家可能段位低但 MMR 其實很高（因為系統還在校準）。

> **▶ 代表作品**：*英雄聯盟、Dota 2、特戰英豪、Apex 英雄*

> **★ 設計要點**：段位系統要同時考慮「挑戰感」（每次升段都有成就感）與「挫折感」（過深的降段懲罰會讓玩家退坑）。業界最常用的折衷：設定「保護段」——低段位不會因為輸太多而掉到更低段位。

### 禁選／選角  `Ban / Pick Phase`

競技遊戲開始前，雙方輪流禁止對方選用特定角色（Ban）、選擇自己要用的角色（Pick）的階段。這是策略遊戲的延伸——透過禁掉對方擅長的角色、搭配己方陣容的羈絆，勝負在對戰開始前就已經開始。電競賽事的 BP 環節往往比對戰本身更有看點。

> **▶ 代表作品**：*英雄聯盟、Dota 2、特戰英豪*

> **★ 設計要點**：BP 系統的複雜度要與角色池大小匹配——角色少的遊戲（如《任天堂明星大亂鬥》）不需要 BP，角色多的遊戲（如《英雄聯盟》150+ 英雄）則必須有 BP 否則 Meta 太單一。

### 版本平衡  `Balance Patch`

定期釋出的調整更新，調整角色、裝備、機制的強弱以維持遊戲健康。理想的平衡 Patch 會：削弱過強的角色（Nerf），強化被冷落的角色（Buff），引入新元素讓 Meta 變化（微調核心系統）。頻率通常是每 2 至 4 週一次小 Patch，每 3 至 6 個月一次大改版。

> **▶ 代表作品**：*英雄聯盟（每 2 週）、Dota 2（不定期的大版本）、特戰英豪*

> **★ 設計要點**：平衡的最高境界不是「所有角色勝率 50%」（這不可能），而是「每個角色在某個情境下都是最好選擇」。無法被選擇的角色等於不存在，即使勝率是 50%。

### 觀戰／重播系統  `Spectator Mode / Replay System`

讓玩家觀看他人遊玩或複盤自己過去比賽的功能。觀戰是電競賽事轉播的核心技術，需要延遲模式（觀眾看到的畫面比選手滯後數秒，防止「天眼」作弊）、導播視角（自動切換到重要打鬥）等功能。重播則讓選手能分析自己的失誤、找出改進方向，是電競訓練的必備工具。

> **▶ 代表作品**：*幾乎所有電競級遊戲*

> **★ 設計要點**：設計重播系統時，記錄的是「輸入資料」（每個玩家按了什麼鍵）而非「畫面影片」。這樣檔案極小（MB 等級）且可任意切換視角。但重播會因為版本更新失效——每次 Patch 都會讓舊重播無法播放是業界難題。

### BO3／BO5  `Best of Three / Best of Five`

電競比賽的勝出制度。BO3 是「三戰兩勝制」（先贏兩場者勝），BO5 是「五戰三勝制」，重大決賽有時採 BO7。長系列賽能減少單場運氣因素、測試選手在不同地圖／不同陣容下的全面能力。

> **▶ 代表作品**：*所有大型電競賽事*

> **★ 設計要點**：BO 的選擇影響觀眾體驗——BO1 節奏快但結果靠運氣，BO5 有深度但耗時長（單場 40 分鐘的 MOBA 打 BO5 需要 3 至 4 小時）。建議小組賽用 BO1 或 BO3，淘汰賽用 BO3 或 BO5。

### 小號／代練  `Smurf / Boosting`

兩種競技遊戲的爭議行為。「小號」（Smurf）指高段位玩家創建新帳號，到低段位虐殺新手——因為新帳號的 MMR 從零開始，但實際操作水準遠超當前段位，對對手與隊友都是災難。「代練」（Boosting）是花錢請高手幫你打到更高段位的服務，是違反遊戲規則的付費作弊。兩者都嚴重破壞競技環境。

> **▶ 代表作品**：*所有有排名系統的競技遊戲*

> **★ 設計要點**：防堵小號的技術：基於帳號綁定的手機／信用卡識別、初期加速 MMR 上調（讓高手小號很快離開低段位）、舉報系統的優先審查。完全杜絕不可能，目標是「控制在可接受範圍」。

### 主播／賽評  `Caster / Commentator`

電競賽事的現場講評人。「Play-by-Play Caster」負責即時描述正在發生的動作（「打野現在過來了！Carry 閃現！中他了！」），像體育轉播的主播；「Color Commentator」（賽評）則負責深度分析戰術、講解背景故事。兩人組合（雙人搭檔）是最常見的轉播格式。在台灣稱為「主播」與「賽評」，中國則常稱「主播」與「解說」。

> **▶ 代表作品**：*英雄聯盟 LPL／LCK／LCS 國際賽事的轉播團隊*

> **★ 設計要點**：優秀的 Caster 能讓一場普通比賽顯得精彩、一場精彩比賽顯得史詩。對遊戲公司而言，培養講評人才與培養選手同等重要——沒有好轉播就沒有電競產業。

### 高幀率／低延遲  `High Refresh Rate / Low Latency`

電競級遊戲對硬體的高要求。高刷新率螢幕（144Hz、240Hz、360Hz）能顯示更多畫面，讓玩家的反應更敏捷。低延遲要求從按鍵輸入到畫面顯示的總延遲（包括螢幕延遲、GPU 渲染延遲、網路延遲）盡可能短，最高等級的電競螢幕+硬體可將這個延遲壓到 10ms 以下。

> **▶ 代表作品**：*電競場地標配*

> **★ 設計要點**：為電競設計的遊戲必須在程式碼層面支援「低輸入延遲模式」（關閉不必要的緩衝與後處理）、提供無邊框視窗模式（避免全螢幕的緩衝延遲）、並公布幀率上限（例如「支援最高 360FPS」）。這些細節對一般玩家無關緊要，但對職業選手是選擇遊戲的關鍵。

# 第十一章：AI 與新興技術

2022 年起的生成式 AI 浪潮正在改變遊戲開發。新的技術帶來新的可能性，也引發新的倫理與商業挑戰。

### 生成式 AI 輔助  `Generative AI Assistance`

使用大語言模型（LLM）、擴散模型（Diffusion Model）等生成式 AI 工具輔助遊戲開發。典型應用：ChatGPT 協助寫劇本大綱與 NPC 對話、Midjourney／Stable Diffusion 生成概念圖、Suno 生成音樂草稿、ElevenLabs 生成語音。這些工具大幅降低了小團隊的製作門檻，但也引發倫理爭議——訓練資料是否有版權問題？AI 作品的版權歸屬？是否會取代人類創作者？

> **▶ 代表作品**：*部分獨立遊戲（特別是 Steam 標示「使用 AI」的作品）*

> **★ 設計要點**：2024 年起 Steam 要求開發者揭露 AI 使用情況。商業作品中過度依賴 AI 可能影響玩家接受度——特別是「AI 生成的角色插圖」很容易被識別出且引發負面評價。建議 AI 作為「輔助工具」加速流程，關鍵美術與劇情仍由人類主導。

### AI NPC  `AI NPC / LLM-Driven NPC`

搭載大語言模型的遊戲角色，能進行開放式對話、根據情境產生獨特反應。傳統 NPC 只能說預設對話，AI NPC 則可以回應玩家的任何問題。NVIDIA ACE（Avatar Cloud Engine）技術讓 AI NPC 能即時生成回應、表情動畫、語音。情緒運算（Affective Computing）與 NPC 的整合正是目前學術與業界的熱點——讓 NPC 不只能說話，還能表達情緒、記得與玩家的互動史。

> **▶ 代表作品**：*Nvidia ACE 技術展示、幾款實驗性獨立遊戲*

> **★ 設計要點**：AI NPC 的挑戰：延遲（雲端 AI 處理需要時間）、一致性（如何確保 NPC 不會說出破壞世界觀的話）、成本（每次對話都要呼叫 LLM API）。目前最實用的方式是「混合式」——預設關鍵對話照腳本，自由對話才用 AI。

### 機器學習程序生成  `Procedural Content Generation via ML (PCGML)`

使用機器學習技術自動生成遊戲內容。與傳統程序生成（基於規則演算法）的差別：PCGML 能從範例中學習風格。例如：訓練模型從《超級瑪利歐》關卡學習，生成類似風格的新關卡；或學習玩家的遊玩習慣，生成適合該玩家的個人化挑戰。

> **▶ 代表作品**：*Nvidia 與微軟的研究專案、部分實驗性作品*

> **★ 設計要點**：PCGML 仍在研究階段，商業應用有限。主要挑戰是「品質控制」——AI 生成的關卡可能不可通關、難度不合理、或缺乏樂趣。需要人類設計師進行篩選與後製。

### AI 升頻與幀生成  `AI Upscaling & Frame Generation`

透過 AI 技術提升畫面品質與幀率。核心技術包括 DLSS、FSR、XeSS（第六章已詳述）。2026 年 DLSS 4.5 的動態多幀生成能為 RTX 50 系列最多產生 6 倍幀率，而 DLSS 5 更邁入「神經渲染」階段（參第六章 DLSS 5 條目）——AI 不只是升頻，而是開始接管渲染本身的邏輯。

> **▶ 代表作品**：*參見第六章 DLSS、路徑追蹤等條目*

> **★ 設計要點**：AI 升頻已是現代遊戲的必備技術——不提供 DLSS/FSR 支援的 3A 遊戲在 PC 平台上幾乎無法生存。設計時應從一開始就考慮 AI 升頻的整合。

### 行為樹／狀態機  `Behavior Tree / Finite State Machine`

AI 敵人行為邏輯的兩種主流實作方式。狀態機（Finite State Machine, FSM）將 AI 分為「巡邏／追擊／攻擊／撤退」等離散狀態，用條件規則在狀態間切換——簡單易寫但容易出現行為僵硬。行為樹（Behavior Tree）則是樹狀結構，讓 AI 依序嘗試各種行為直到找到能執行的一個——更靈活，現代遊戲的標準做法。

> **▶ 代表作品**：*幾乎所有 3D 遊戲的 AI 敵人*

> **★ 設計要點**：在 Unity 中可用 Behavior Designer 等外掛建立行為樹；在 Unreal 中內建行為樹編輯器。對於動作／射擊遊戲，建議學習行為樹而非 FSM——行為樹的可擴展性遠優。

### 即時語音 AI  `Real-time Voice AI`

將 AI 生成的語音即時套用到遊戲角色上的技術。典型應用：AI NPC 的即時語音回應、玩家自訂角色的客製化配音、遊戲中的即時語音翻譯（玩家說中文、隊友聽到英文）。ElevenLabs、Nvidia ACE 等平台提供這類服務，品質已接近真人配音。

> **▶ 代表作品**：*部分 AI NPC 實驗作品*

> **★ 設計要點**：語音 AI 的倫理議題：使用他人聲音訓練的 AI 聲音（Voice Cloning）是否侵權？配音演員的工作是否會被取代？建議使用授權明確的語音平台，並在遊戲中清楚揭露使用 AI。

### 雲端遊戲  `Cloud Gaming`

遊戲在雲端伺服器運算、畫面串流到玩家裝置的服務。玩家不需要高階硬體——手機、平板、低階 PC 都能跑出 RTX 4090 的畫質。主要服務包括 GeForce Now、Xbox Cloud Gaming、Amazon Luna、PlayStation Plus Premium 的雲端功能。限制是網路要求極高（穩定 25 Mbps 以上）與無法避免的輸入延遲。

> **▶ 代表作品**：*GeForce Now、Xbox Cloud Gaming、Amazon Luna*

> **★ 設計要點**：雲端遊戲在亞洲（特別是台灣）受網路基礎建設與資料中心位置限制，延遲高於歐美。目前更適合作為「補充」（讓玩家在低階裝置上預覽）而非「主要管道」。

### 區塊鏈遊戲／Web3  `Blockchain Game / Web3 Gaming / NFT`

使用區塊鏈技術的遊戲。核心概念：遊戲道具（角色、裝備、土地）以 NFT 形式存在，玩家真正「擁有」這些資產、可在二級市場自由交易。2021 至 2022 年的 Axie Infinity 曾掀起「Play-to-Earn」熱潮，隨後因經濟模型崩壞、加密貨幣熊市等因素衰退。目前區塊鏈遊戲仍是小眾領域，但部分專案在探索新的融合方式。

> **▶ 代表作品**：*Axie Infinity、Gods Unchained、部分 GaaS 遊戲的實驗性功能*

> **★ 設計要點**：主流遊戲玩家對 NFT 有強烈反感——Steam 已禁止含 NFT 的遊戲上架、Ubisoft 與多家大廠的 NFT 嘗試均告失敗。作為開發者，納入 NFT 需要極謹慎評估社群反應。

### 元宇宙  `Metaverse`

一個持續性、跨平台、集合虛擬世界、社交、經濟、數位身份的概念框架。2021 年 Meta（原 Facebook）改名引發元宇宙炒作熱潮，但隨後實際產品（Horizon Worlds）表現不佳，熱度已消退。目前最接近「元宇宙」概念的實際產品是 Roblox、Fortnite Creative、Minecraft、VRChat——而這些嚴格來說是「沙盒＋社交」的大型多人平台。

> **▶ 代表作品**：*Roblox、Fortnite Creative、VRChat、部分 Zepeto 應用*

> **★ 設計要點**：「元宇宙」作為行銷詞已過熱，業界逐漸回歸務實用語如「3D 互動平台」「虛擬社交空間」。對開發者的啟示：創造有意義的社交連結比追逐虛幻概念更重要。

# 第十二章：遊戲圈黑話與玩家社群術語

本章收錄遊戲玩家社群中最常出現的俚語、黑話與縮寫。這些詞彙在官方教學裡幾乎永遠不會出現，但在 Discord 聊天室、Twitch 實況、PTT／巴哈姆特、YouTube 留言區裡每天上演。作為遊戲企劃或老師，能「聽懂玩家在說什麼」是理解社群文化的前提。

注意：本章收錄的詞彙以台灣遊戲圈常用語為主，部分會對照中國、日本用法。部分詞彙帶有一定程度的戲謔或自嘲意味，使用時須注意場合。

## 十二之一：MOBA 與團隊競技戰場黑話

這組詞彙源自《英雄聯盟》《Dota》等 MOBA 遊戲，因電競轉播與實況普及，已經滲透到所有團隊競技的語境。

Carry / 帶飛 (Carry)：指一個人強到可以憑己之力帶隊伍贏比賽。引申義是「很罩、很強」。生活語：「這次專案靠他 Carry」。Hard Carry 則是「超強的 Carry」。

大腿 (Thicc Leg)：隊伍中最強的那個，大家都抱著他的大腿混勝場。「抱大腿」就是跟著強者打。

Gank (Gang Kill)：偷襲、圍毆。Gang Bang Kill 的縮寫，指多人包抄擊殺落單的敵人。反 Gank（Counter-gank）是識破對方 Gank 並反過來圍殺。生活語：「下班前被主管 Gank 了」。

Farm / 農兵 / 種田 (Farming)：在比賽初期透過擊殺小兵、野怪來賺錢升級的過程。Farm 的技術高低直接決定後期強弱。

CS (Creep Score / Creeping Score)：補兵數。英雄聯盟中殺死一個小兵得一分 CS。CS 分數是評估對線期表現的客觀指標。

KS / 搶人頭 (Kill Steal)：隊友已經把敵人血量削到殘血、你才補最後一刀拿走人頭。長期 KS 會引發隊友不滿。

Feed / 送頭 (Feeding)：被敵人殺死，讓對方獲得擊殺獎勵。送很多頭的人稱 Feeder，會讓敵方 Carry 滾雪球（Snowball）。「不要再 Feed 了」是隊友最常說的怒吼之一。

BD / 偷家 / 偷塔 (Backdoor)：趁對方主力在別處團戰時，獨自潛入對方基地拆建築。成功偷家是奇蹟等級的逆轉戰術。

Dive / 越塔 (Dive (Tower Dive))：在明知會被塔打的情況下，衝進塔下擊殺敵方英雄。高風險高報酬的戰術。

Poke / 騷擾 (Poke)：用遠程技能反覆消耗對手血量，不求擊殺但求壓制。

Push / 推線 (Push)：把己方小兵一路推到敵方塔下的戰術。好處是給敵方壓力，風險是自己孤軍深入容易被 Gank。

Int / 故意送 (Intentional Feeding)：故意送死的行為，通常是擺爛玩家或輸到崩潰者所為，在所有競技遊戲中都是違規行為。

Snowball / 滾雪球 (Snowball)：取得優勢後優勢越滾越大的現象。初期被 Feed 的英雄會因為裝備領先而更好 Farm，然後越打越強。

## 十二之二：通用聊天與情緒縮寫

GG (Good Game)：好一場比賽，原為比賽結束的禮貌用語（傳統上由輸的一方先說）。現已泛化為「完蛋了」「結束了」的嘆詞，例如「這季度業績 GG 了」。

GGEZ (Good Game, Easy)：「贏得很輕鬆」的挑釁用語。多數遊戲已經禁止或會把它自動替換成搞笑字串（Blizzard 的作法）。

GLHF (Good Luck, Have Fun)：「祝好運、玩得開心」的賽前問候。職業賽事中選手握手時常說。

BRB (Be Right Back)：馬上回來。上廁所、門鈴響時打的。

AFK (Away From Keyboard)：人不在鍵盤前。多人遊戲中被掛機的隊友會被罵「別 AFK」。

Noob / Newbie / Newb (Noob / Newbie)：新手。Newbie 是中性詞，Noob 則帶有貶意，源自「新手但還死不認錯」的形象。台語諧音常寫「嫩 B」。

Smurf / 小號 (Smurf)：高段位玩家用低等級帳號進入低段位對戰的行為，在所有排名制遊戲中都是社群公敵。

666 / 777 (666 / 777)：666 源自中國網路用語，讚嘆「很溜、很牛」的意思。由於台灣遊戲實況主亞洲統神力推「台灣人要不一樣」的說法，777 在台灣遊戲圈也逐漸流行，作為台灣版的「讚爆」。

WTF / WTH (What the F / What the Hell)：「搞什麼鬼」。驚訝或不滿時脫口而出。

Lag / 頓 / 卡 (Lag)：網路延遲造成的畫面頓挫。「我剛剛 Lag 了」是被擊敗時最常用的理由（真的假的請自行判斷）。

## 十二之三：角色定位與職業分工俚語

肉盾 / 坦克 / 神坦 (Tank)：血厚裝甲厚、專吸引敵方火力的角色。神坦是「超硬」的意思。

奶媽 / 補師 (Healer)：負責幫隊友回血的治療職。「我家奶媽跑得比誰都快」是經典吐槽。

輸出 / DPS / 打手 (Damage Dealer / DPS)：專門造成傷害的角色，團隊勝負的關鍵。

脆皮 / 玻璃砲 (Glass Cannon)：傷害極高但血量極少、被碰一下就死的角色。通常指法師或狙擊手。

輔助 / Support (Support)：不主要造傷，而是以 Buff、保護、視野支援隊友的角色。

AD / AP / AD Carry / ADC (Attack Damage / Ability Power / ADC)：AD 是物理傷害、AP 是魔法傷害。ADC（AD Carry）是依靠物理傷害 Carry 的遠程輸出，即「射手」。

打野 (Jungler)：MOBA 中負責野區（地圖中央區域）打野怪、到各路 Gank 的角色。節奏掌控者。

## 十二之四：戰鬥與動作語

秒殺 / 秒 (One-Shot)：一招擊殺對手。「這隻 Boss 被他三秒」即三秒之內被擊敗。

放大 / 大招 / Ult (Ultimate (Ult))：角色的終極技能。「我的大還沒好」指大招在冷卻中。

舔包 / 舔袋 (Loot)：擊敗敵人後撿走對方掉落物的行為。源自 FPS 與 BR 遊戲。「打完先舔個包」。

空投 (Supply Drop / Airdrop)：吃雞遊戲中的空投補給箱。「搶空投」是高風險高報酬的決策。

剛正面 (Go Head-On)：選擇正面衝突而非迂迴。「別苟了，剛正面！」

苟 / 龜 (Camp / Turtling)：消極防守、躲角落的打法。「苟到最後」是某些 BR 類遊戲的有效戰術。

卡 BUG / Exploit (Exploit)：利用遊戲 BUG 獲得優勢的行為。部分是單人遊戲的樂趣，但在線上遊戲是違規行為。

速通 (Speedrun)：追求以最短時間通關的挑戰。Any% 指「用任何手段」最快通關，100% 指「收集所有東西」最快通關。世界紀錄會公開在 Speedrun.com。

卡等 / 越級打怪 (Level-gating / Under-level)：刻意不升等級，用低等級挑戰高階 Boss 的硬核玩法。

## 十二之五：手遊與抽卡文化俚語

課金 vs 氪金 vs 儲值 (Pay / Top-up)：三個意義相同但文化來源不同的詞：「課金」源自日文「課金（かきん）」，台灣用；「氪金」是中國網路諧音梗（氪≈課）；「儲值」是中性、官方用語。注意用法能判斷對方大致的背景。

鯨魚 / 巨鯨 (Whale / Mega-whale)：重度消費的玩家。單款手遊課超過十萬台幣算中型鯨魚，百萬以上算巨鯨。手遊營收 80% 以上來自這 5% 的玩家。

無課 / 微課 / 重課 (F2P / Low-spender / Whale)：對課金深度的三種分類。無課（F2P, Free-to-Play）是完全不花錢、微課是少量課金（例如只買月卡）、重課則是動輒上萬的消費者。

歐洲人 / 非洲人 (Lucky / Unlucky)：運氣好的玩家叫歐洲人（意象上「臉白」）、運氣差的叫非洲人（「臉黑」）。「讓我吸點歐氣」是抽卡前的常見玩笑。注意這組比喻近年因種族敏感性引發討論，部分社群已改用「歐派／非派」中性說法。

保底 / 出貨 (Pity / Hit)：保底（Pity System）指連續未抽到最高稀有度後必出的機制。出貨指成功抽到想要的角色。「我 180 抽才出貨」是慘痛經驗談。

首抽 / Reroll (Reroll)：反覆刪除重來新帳號直到抽到強角的行為，見第九章詳述。

Tier List (Tier List)：角色強度排行榜，見第九章詳述。手遊玩家抽卡前必看的資料之一。

## 十二之六：版本與平衡性黑話

Nerf / 削 (Nerf (verb))：動詞，指在版本更新中把某角色或裝備調弱。「這隻下個版本被 Nerf 了」。

Buff / 加強 (Buff (verb))：與 Nerf 相反的動詞，指把某角色調強。注意「Buff 增益狀態」與「Buff 加強動詞」是同字雙義，見第三章。

OP (Over Powered)：強到破壞平衡。「這隻太 OP 了」是削弱呼聲的起點。

IMBA / 不平衡 (Imbalanced)：OP 的同義詞。「這版本非常 IMBA」。

版本賤男 / 版本答案 (Meta Pick / Current OP)：這個版本公認最強的角色。選他幾乎等於選勝利。

廢料 / 板凳 (Bench-warmer / Trash Tier)：完全沒有競爭力、被放在倉庫吃灰的角色。

改版 / Patch (Patch / Update)：官方推出的修正與平衡更新。重要更新稱為「大改版」，小調整稱為「小 Patch」或「Hot Fix」。

## 十二之七：遊戲時間與玩家狀態黑話

肝 / 爆肝 (Grinding)：長時間不眠不休地遊玩。「肝了一個禮拜總算破關」。源自「為遊戲熬夜傷肝」的誇張比喻。衍生「日常肝」指每天固定要打的內容。

掛機 (Idle / AFK-farming)：開著遊戲但沒在操作，讓角色自動進行某些動作（例如掛機掛網賺錢）。在團隊遊戲中則是直接擺爛的行為。

退坑 / 棄坑 (Quit)：停止玩某款遊戲。「退坑原神」。

回坑 (Return)：離開後又回來玩。「看到新角色我就回坑了」。

補坑 / 入坑 (Catch Up / Get Into It)：開始玩一款新遊戲，或補完以前沒玩的作品。

Cooldown / CD / 冷卻中 (Cooldown)：技能冷卻中，見第三章。口語上也指「心靈冷卻期」——剛受挫折不想再打。

## 十二之八：操作與設備黑話

WASD (WASD (PC 移動鍵))：PC 遊戲預設的移動控制鍵。W 上、S 下、A 左、D 右。「WASD 黨」指用鍵盤滑鼠玩遊戲的玩家。

QWER (QWER (技能鍵))：MOBA 中四個主動技能的預設按鍵（Q、W、E、R）。「R 鍵冷卻」即大招在冷卻。

手把黨 / PC 黨 / 主機黨 (Controller / PC / Console)：依輸入裝置與平台分的玩家族群。主機黨與 PC 黨有經典的「誰比較高貴」之爭（通常是玩笑）。

Ping 值 (Ping)：網路延遲指標，見第五章詳述。口語「我 Ping 高」即「我網路不好」。

幀數 / FPS (Frame Rate)：每秒畫面數，見第六章詳述。「我只有 30 幀」常作為打不好的藉口。

開圖 / 掛輔 (Maphack / Hack)：作弊程式。「開圖」是指用外掛看到整張地圖（應該被霧遮住的部分）。

## 十二之九：廠商與社群文化黑話

廠商聖光 / 廠商黑幕 (Devs' Will)：玩家戲稱遊戲設計的詭異之處。「這次抽卡臉這麼黑，一定是廠商黑幕」——明知是心理錯覺但玩家愛說。

更新信仰 / 信仰充值 (Faith Refill)：嘲諷廠商「只要繼續更新就會有玩家持續課金」的情況。

跳票 (Delay)：預定發售日延後。「又跳票了」——在大型 3A 是家常便飯。

難民 / 難民潮 (Refugee)：某款遊戲出事（伺服器關閉、重大爭議），玩家集體遷徙到類似遊戲的現象。「天堂難民」「星城難民」。

洗版 / 洗樓 (Flood / Spam)：在討論板或聊天室連續發大量訊息。

釣魚 / 帶風向 (Fishing / Agenda Pushing)：發文試探反應或故意引導風向的行為。

神作 / 神 Game (Masterpiece)：「這款簡直是神作」——極高評價。相對的是「雷作」「垃圾 Game」。

雷包 (Landmine)：隊友很爛。「這局遇到四個雷包」。

大佬 / 巴哥 / 大神 (Pro Player)：高手玩家的尊稱。

萌新 / 新人 (Newbie)：新手玩家的可愛稱呼（與帶貶意的 Noob 不同）。

# 結語

遊戲產業是一個快速變化的領域。今天的新技術明天就可能成為標準，今天的主流類型後天就可能被新興類型取代。2026 年 3 月剛剛發表的 DLSS 5 神經渲染技術、本月才出現的玩家社群梗，都在提醒我們：遊戲的世界永遠在前進。

但在所有的變化之下，有些事情是不變的。「心流」理論從 1975 年提出至今仍是最佳體驗設計的圭臬；箱庭遊戲的密度哲學從《超級瑪利歐 64》到《薩爾達傳說 王國之淚》持續進化；分支敘事從《柏德之門》初代到《柏德之門 3》證明了玩家代理感的永恆價值。真正的設計功力不在於追逐每一個新詞彙，而在於理解這些詞彙背後的設計邏輯——為什麼這個機制能讓玩家感到樂趣？為什麼那種敘事結構能打動人心？

對於遊戲開發者而言，這些專有名詞是與同儕溝通的語言，是閱讀設計文件的基礎，是理解產業趨勢的鑰匙。但請記住：詞彙只是工具，真正重要的是如何運用這些概念來創造優秀的遊戲體驗。沒有任何術語清單能取代「坐下來真的把遊戲做出來」的實踐——玩家不會記得你的 GDD 寫得多好、用了什麼前沿技術，他們只會記得那個讓他們在凌晨四點還捨不得關機的瞬間。

本指南記錄了截至 2026 年 4 月為止遊戲產業的專有名詞現況。隨著 DLSS 5 在 2026 年秋季上市、下一代主機在未來幾年問世、生成式 AI 在遊戲製作中的角色擴大，必然會出現新的術語、新的設計範式、新的玩家文化。希望讀者能以本書作為起點，持續追蹤新的發展，保持對這個行業的熱情與好奇心。
